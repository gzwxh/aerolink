# 通知与公告

通知分两种：给个人的**通知**（站内信与邮件，按事件投递）和给所有人的**公告**（顶栏横幅）。两者都在「系统设置 → 通知管理」里配置。

## 站内信

站内信在顶栏的**铃铛**里，没有独立的通知列表页：

- 未读数是每 60 秒轮询一次；弹层打开时才拉取列表，只展示最新 20 条。
- 点击某一条即把它标记为已读；也可以「全部已读」，或「清空全部」（有二次确认）。
- 未读数超过 99 显示为 `99+`。
- 站内信**不会自动清理**，会一直保留到用户自己清空；也无法按事件类型或已读状态筛选。

## 事件与必收口径

目前有 14 类事件（外加一个供配置自检的「测试」事件）：

| 事件 | 触发时机 |
| --- | --- |
| 异地登录 | 登录 IP 不属于常用登录城市时（由「安全管理 → 认证安全」的「异地登录通知」开关控制） |
| 密码即将过期 / 密码已过期 | 每日检查：密码过期前两天内每天提醒一次 |
| 账号即将过期 / 账号已停用 / 账号已启用 | 每日检查与管理员操作 |
| 长期未登录自动禁用 | 每日检查（阈值见「安全管理」的不活跃用户自动禁用） |
| 会话被顶下线 | 同一账号在别处登录顶掉了当前会话 |
| 密码被管理员重置 / 动态码被管理员重置 | 管理员在用户详情里的操作 |
| 角色被分配 / 角色被移除 | 权限变更 |
| 定时任务失败 | 定时任务执行失败 |
| 邮件投递失败 | 邮件发送失败（只会进站内信） |

**必收**事件不受订阅开关影响，且只投递到站内信（邮件是否发送仍取决于订阅与 SMTP 配置）：

- **管理员必收**：密码被重置、动态码被重置、角色被分配、角色被移除、邮件投递失败。这类事件无条件并上全部管理员。
- **当事人必收**：异地登录、密码过期（含即将过期）、账号到期、账号停用 / 启用、长期未登录停用、会话被顶下线、定时任务失败等。这类事件无条件并上当事人——**即使账号此刻正处于停用状态**，停用的通知也能收到。

其余事件按下面的订阅规则投递。

## 邮件

「系统设置 → 通知管理 → 邮件设置」里配置 SMTP：

| 项 | 说明 |
| --- | --- |
| SMTP 地址 / 端口 | 默认端口 465 |
| 用户名 / 口令 | 口令单独加密存储；留空表示不修改已保存的口令 |
| 发件地址 / 发件人名称 | 收件人看到发件人 |
| 加密方式 | `none` / `starttls` / `ssl`（默认 `ssl`）；自签证书可跳过服务端证书校验 |
| 密码过期提前天数 | 默认 7 天 |
| 站内信 / 邮件开关 | 两个渠道各一个开关；**两个都关掉就不再产生任何通知** |

同一页上还有两个按钮：**测试发送**（用已保存的配置给指定收件人发一封邮件，用于验证 SMTP 是否通）和**立即执行每日检查**（手动触发一次密码过期、账号到期等每日检查，不必等到后台跑）。

### 邮件模板

每个事件一份模板（标题 + 正文 + 是否启用），可自定义，正文里用 `{{变量}}` 占位。渲染时未知占位符**原样保留**（便于发现写错的变量名）。邮件是**纯文本**，不支持 HTML 与附件。

各事件可用占位符：

| 事件 | 占位符 |
| --- | --- |
| 异地登录 | `username`、`ip`、`time`、`provider`、`userAgent` |
| 密码即将过期 | `username`、`days`、`expireDate` |
| 密码已过期 | `username`、`expireDate` |
| 长期未登录自动禁用 | `username`、`days` |
| 账号即将过期 | `username`、`days`、`expireDate` |
| 账号停用 / 启用 | `username`、`operator`、`time` |
| 密码被重置 | `username`、`operator`、`time` |
| 角色分配 / 移除 | `username`、`role`、`time` |
| 邮件投递失败 | `time`、`address`、`event`、`reason` |
| 定时任务失败 | `taskName`、`taskType`、`cluster`、`key`、`reason`、`time` |
| 测试 | `time` |

邮件投递失败时会给管理员写一条站内信，同一失败原因 1 小时内只提醒一次，避免刷屏。

## 订阅

「系统设置 → 通知管理 → 订阅」按「事件 × 渠道 × 接收人」配置：

| 字段 | 取值 |
| --- | --- |
| 事件 | 上面的事件列表，支持批量全选 |
| 渠道 | 站内信 / 邮件 |
| 接收人类型 | 指定用户、指定邮箱、全体已启用用户 |
| 接收人 | 依接收人类型填写 |

两条约束：指定用户时该用户必须已配置邮箱；「指定邮箱」类型只能选邮件渠道。订阅列表里可以看到已配置的订阅并逐条开关或删除。

**粒度限制**：订阅只有「事件 × 渠道 × 接收人」三个维度，**没有集群、命名空间、资源类型的维度**——比如无法做到「只订阅 prod 集群的定时任务失败」。

## 公告

「系统设置 → 通知管理 → 公告」创建面向所有登录用户的顶栏横幅。

| 字段 | 说明 |
| --- | --- |
| 标题 | 最长 255 字符 |
| 正文 | 最长 8192 字符，支持 Markdown 子集与具名颜色标记（如 `{warning}今晚停服{/warning}`），**不接受原始 HTML** |
| 级别 | 信息 / 警告 / 危险 |
| 优先级 | 决定多条公告同时生效时的展示顺序 |
| 生效时间 / 结束时间 | 留空表示立即生效 / 永不过期；结束时间必须晚于生效时间 |
| 滚动方式 | 不滚动 / 连续滚动 / 定速滚动 |
| 启用 | 关闭后立即从顶栏消失 |

展示规则：

- 只展示**启用中、已到生效时间、未过结束时间**的公告；多条同时生效时合并成一条轨道，级别取其中最高的。
- 横幅可以悬停暂停、拖动，也可以展开看全文。
- 同时生效的公告上限是 **20 条**。
- 公告是**全局**的：没有目标用户 / 受众字段，也没有已读状态，用户无法关闭或「不再提示」，只能等结束时间到期或管理员关掉。

## 权限

「通知管理」章节下的全部接口——邮件设置、模板、订阅、公告——都归 **`settings.notification`** 这一个章节权限（公告没有单独的权限位），并且都在管理员 API 组下，需要先具备管理员身份。章节权限的分配见 [RBAC 配置指南](../config/rbac-config.md)。

用户侧没有通知偏好设置页：普通用户只能接收，能做的操作就是站内信的「全部已读」和「清空」。
