# 节点终端镜像按节点架构选 `-arm64`

日期：2026-11-07
状态：已实现

## 1. 背景与结论

节点终端的 Agent Pod 用 `Spec.NodeName` 直接绑到用户点开的这台节点上
（`pkg/terminal/node_terminal_handler.go`），但镜像名只有一个全局值：
`general_settings.node_terminal_image`，空则回落 `common.NodeTerminalImage`
（默认 `swr.cn-south-1.myhuaweicloud.com/gzwxh/busybox:latest`）。

公司 SWR 里 `gzwxh/busybox` 的 `latest` / `1.36` / `1.37` 都是**单架构 amd64** manifest
（不是 manifest list），所以 arm64 节点上开节点终端必定 `exec format error`；混合架构集群
里改设置也没用——同一个镜像名不可能同时满足两种架构。

结论：把「按节点架构挑镜像」这件事放进代码，沿用 SWR 既有的 `-arm64` 后缀独立 tag 口径
（同 `openeuler:24.03-lts-sp4-arm64`、`aerolink:v1.0.2-arm64`）。SWR 对 manifest list 的
解析不可靠，也不支持同 tag 多架构，所以不做多架构 tag。不加库列、不加环境变量、不加界面
开关；arm64 那份 busybox 已用 `skopeo copy --format v2s2 --remove-signatures
--override-arch arm64` 从 `docker.m.daocloud.io/library/busybox:latest` 转推进 SWR，
tag 为 `gzwxh/busybox:latest-arm64`（`linux/arm64/v8`，manifest `sha256:241c6a14…`）。

## 2. 改写规则

架构取值优先级：`Status.NodeInfo.Architecture` → 节点标签 `kubernetes.io/arch` →
`beta.kubernetes.io/arch`；都拿不到就当作非 arm64，行为与改动前一致。

只有「显式带 tag、不是 digest 引用、tag 还没带 `-arm64` 后缀」三条都满足才改写，
其余原样返回：

| 输入（arm64 节点） | 结果 | 理由 |
| --- | --- | --- |
| `swr…/busybox:latest` | `swr…/busybox:latest-arm64` | 常规情形 |
| `reg:5000/team/busybox:1.2` | `reg:5000/team/busybox:1.2-arm64` | tag 分隔符只认最后一个 `/` 之后的冒号，端口号不受影响 |
| `busybox` | 不变 | 不带 tag 的名字多指向上游多架构镜像，加后缀反而把能跑的改坏 |
| `repo/busybox@sha256:…` | 不变 | digest 已锁死架构 |
| `swr…/busybox:latest-arm64` | 不变 | 幂等，不叠第二层后缀 |
| 任何值（amd64 / 架构未知） | 不变 | 只处理 arm64 |

改写落空的最坏结果是 `ImagePullBackoff`；arm64 节点上用 amd64 镜像原本是必定起不来的，
所以没有先去做仓库探测（后端也没有访问私有仓库的凭据口径）。真遇到「arm64 镜像不带
`-arm64` 后缀」的集群，把完整镜像名直接填进界面即可；若成规模出现，再补显式配置项。

## 4. 验证

```bash
go test ./pkg/terminal/ -run 'TestNodeArchitecture|TestApplyNodeArchImage' -v   # 全过
go build ./...
```

arm64 镜像侧（Kylin V10 aarch64 验证机）：`docker run --rm --entrypoint uname
swr.cn-south-1.myhuaweicloud.com/gzwxh/busybox:latest-arm64 -m` 期望 `aarch64`，并确认层内
`/bin/sh`、`/bin/chroot`、`/bin/nsenter` 齐备——终端命令是
`chroot /host || (exec /bin/zsh || exec /bin/bash || exec /bin/sh)`。

集群侧（有 arm64 节点时）：开节点终端后检查 Agent Pod 的
`.spec.containers[0].image` 应为 `…busybox:latest-arm64`，amd64 节点保持 `…busybox:latest`。
注意终端 Pod 是 `ImagePullPolicy: IfNotPresent`，节点上若有同名的手工标签会掩盖真实拉取行为，
验证以带 `-arm64` 的新 tag 名为准。

## 5. 不在本次范围

- `KUBECTL_TERMINAL_IMAGE`：kubectl Agent 不绑节点（无 `NodeName`/`nodeSelector`），
  纯 ARM 集群里同样可能被调度到 arm64 节点而失败，但那是另一个镜像与另一条路径。
- Pod 调试容器默认镜像 `busybox:1.37`（`ui/src/components/pod-debug-dialog.tsx`）仍是
  amd64；需要时按同一口径补 `1.37-arm64`，界面里也可手工填写 arm64 镜像名。
- 其它架构（`s390x`、`mips64le` 等）不做后缀改写，内网没有这类节点。
