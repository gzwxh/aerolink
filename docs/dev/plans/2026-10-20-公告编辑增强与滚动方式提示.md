# 公告编辑增强与滚动方式提示（2026-10-20）

## 背景

线上（`aerolink.gogdev.cn` §设置 → 通知 → 公告）反馈三条问题：

1. 编辑公告的工具栏功能太少；
2. 不支持 Markdown；
3. 滚动方式「选了不生效」。

核实结论见下，处置按「能改的改、改不动的说清楚」拆分。

## 现状核实

- **工具条**只有加粗 / 斜体 / 删除线 / 文字颜色（`announcement-editor.tsx`）。展示侧白名单
  `['p','strong','em','del','code','a','br']` 里已经有 `code` 与 `a`，但编辑器没有入口，
  也把这两类字符转义掉了，所以等于不可用。
- **Markdown 不生效是刻意的**：`escapeMarkdown` 把 `* _ ~ [ ] { } | # \` 全部转成 `\X` 后
  落库（`lib/announcement-editor.ts`），这样「编辑区里是什么、顶栏就是什么」。代价是
  管理员无法在界面里写 Markdown。块级元素（标题/列表/引用/表格）即便写进库，也会被
  `unwrapDisallowed` 拆成纯文字。
- **滚动方式**数据链路完整（UI → `scrollMode` → 后端解析并同步 `scroll` → 读取回传），
  单条公告时确实生效（`announcement-scroll.test.ts` 覆盖）。看起来「没生效」的真实原因
  是通知栏把**所有生效公告串成一条轨道**，方式取最强（`paced > continuous > none`），
  只要还有任何一条生效公告是滚动/停留，另一条的「不滚动」就没有可见变化，而界面上没有
  任何提示。

## 方案

### A. 滚动方式：不改语义，改为把合并规则摆在界面上

拆成「每段各自滚动」不现实：顶栏只有一行，静态段会把滚动段挤走，且现有动画是整条轨道
一个 `translateX`。因此保留「取最强」，改由界面解释：

- 编辑对话框：当本条选的模式弱于**其他生效公告**的合并结果时，在「滚动方式」下方给出
  提示（写明另外那几条实际按什么滚）；
- 列表行：生效中的公告若其自身模式与合并结果不一致，在滚动方式后标出「实际：X」。

### B. 工具栏补齐：链接、行内代码、清除格式

这三项存储格式与渲染链路都已支持，只缺编辑器这一层：

- 链接：`[文字](url)` ↔ `<a href>`；URL 只放行 `http(s)://` 与 `mailto:`（与 react-markdown
  默认 `urlTransform` 同口径），序列化时把 `(`、`)`、空格百分号编码，避免破坏标记解析；
- 行内代码：`` `code` `` ↔ `<code>`；编辑器里点链接不跳转（`preventDefault`）；
- 清除格式：摘掉选区内 `strong/em/del/code/a/颜色 span`，文字保留。

### C. Markdown：源码模式 + 块级行内化

不在所见即所得里「边打边解释 Markdown」——那正是 §12.13 之前踩过的坑（输入区显示星号、
展示侧却渲染成加粗）。改为**显式模式切换**：

- 「所见即所得」：现有行为不变（元字符仍转义）；
- 「Markdown」：`textarea` 直写原文（不转义）+ 下方实时预览，走与顶栏完全相同的
  `AnnouncementContent`。预览此时是**必要**的，因为输入区不再是最终效果。

同时把展示侧白名单扩到块级，并做**行内化**（横幅是单行轨道，块级只能退化成行内）：

| Markdown | 行内化结果 |
| --- | --- |
| `# 标题` ~ `###### 标题` | `<strong>标题</strong> ` |
| `- 项` / `1. 项` | `• 项 `（有序列表同样用点号，单行里序号没有意义） |
| `> 引用` | 斜体 |
| `---` | `——` |
| 表格单元格 | 单元格文字 + 空格 |

`pre`、`img`、`table/tr` 仍不进白名单（`unwrapDisallowed` 只留文字），避免把大段代码或
外部图片塞进一行横幅。

## 不做的事

- 不做「每条公告各自滚动方式」的渲染改造（见 A）；
- 不支持 HTML（不加 `rehype-raw`）、不允许任意色值；
- 不引入富文本编辑依赖（沿用自写的 Range 包裹，便于单测）。

## 验证

- `lib/announcement-editor.test.ts`：链接/代码往返、URL 白名单拒绝 `javascript:`；
- `components/announcement-editor.test.tsx`：链接按钮、清除格式、Markdown 模式不转义；
- `components/announcement-content.test.tsx`（新增）：标题/列表/引用/分割线的行内化；
- `components/settings/announcement-management.test.tsx`：滚动方式冲突提示；

## 追加：滚动速度 / 每轮停留 / 显示时长（同日第二轮反馈）

用户反馈「滚动速度、每轮停留是写死的，也没有显示时长字段」。三个都做成**每条公告各配**，
与「滚动方式」同一套合并口径。

| 参数 | 字段 | 范围 | 默认 | 语义 |
| --- | --- | --- | --- | --- |
| 滚动速度 | `scrollSpeed` | 10~300 px/s | 60 | 自动模式下按「内容宽度 ÷ 速度」算一轮时长 |
| 每轮停留 | `pauseSeconds` | 1~60 秒 | 2 | 只在 paced 下生效，加在滚动段之后 |
| 显示时长 | `displaySeconds` | 3~600 秒，0=自动 | 0 | 直接指定**滚动段**秒数，填了就不再按速度换算，也不套 15 秒下限 |

### 合并规则（一条轨道只有一套参数）

方式取最强（paced > continuous > none）、**速度取最慢**、每轮停留与显示时长取**最长**。
口径与「级别取最高」一致：任何一条公告提出的要求都不会被另一条悄悄降级；速度取最慢是
因为快的盖掉慢的会让长内容来不及读。正因为会合并，编辑弹窗与列表都要写出「实际：…」，
否则又会变成「改了没生效」。

### 关键取舍

- **默认值 = 升级前写死的常量**，所以加列不需要回填：AutoMigrate 补列时给存量行填的默认值
  就是 60 / 2 / 0（`pkg/model/announcement_test.go` 里用「删列再迁移」把这个升级路径钉住了）。
- **显示时长只覆盖滚动段**，「每轮停留」的停顿另加，两者不重叠——避免「停留比时长还长」
  这种没法解释的组合，也让关键帧的停留点始终是 `滚动 / (滚动 + 停留)`。
- **填了显示时长就把速度输入置灰**：速度确实不参与计算了，留着可编辑只会招来
  「改了速度没反应」。
- 越界一律显式报错（400 + 具体区间），不悄悄夹到边界，否则管理员以为存的是自己填的值。
- `pauseSeconds` 下限是 1 而不是 0：停 0 秒等于连续滚动，那是另一个 `scrollMode`。

### 验证

- `pkg/announcement/handler_test.go`：默认值落库、显式值落库并回读、覆盖式 PUT 不丢参数、
  六种越界各自 400；
- `pkg/model/announcement_test.go`：删列再迁移后存量行拿到 60/2/0；
- `ui/src/lib/announcement-scroll.test.ts`：缺字段/非法值回落、四项合并规则、停留点随停顿时长变化；
- `ui/src/components/announcement-bar.test.tsx`：速度换算、显示时长优先且不套下限、停留时长可配、
  多条取最慢；
- `ui/src/components/settings/announcement-management.test.tsx`：三个输入回传、填了显示时长后
  速度置灰、列表标出「实际」值。

## 追加：标题可选、空公告拦截、输入可清空、弹窗预览（同日第三轮反馈）

用户三条反馈：① 标题应当可选，但标题与正文都空时不能启用；② 「每轮停留」设了好像不生效；
③ 速度/停留输入框要能清空重输，弹窗里最好直接在预览处看到滚动效果。

### ① 标题可选 + 空公告拦截

- `pkg/announcement/handler.go` 去掉「请填写标题」，只保留 255 字长度校验；空白标题落库空串。
- 顶栏按「有标题才渲染标题 + 冒号」处理（空标题原本会渲染一个空加粗块 + 孤零零的「：」），
  纯文本复述与展开全文弹层同样跳过空标题；管理列表用「无标题」占位。
- 标题可选之后才有「两者都空」的草稿：后端显式返回「标题和内容不能同时为空」（正文仍必填），
  前端在正文为空时显示原因并禁用保存，因此这种公告既存不下来也启用不了。

### ② 「每轮停留」不生效：合并时默认值参与了比较

`combinedScrollParams` 原先以默认值 60 / 2 作为初值再逐条取 min/max，于是**单条公告填的
100 px/s 会被 60 盖掉、填的 1 秒停留会被 2 秒盖掉**——只有「更慢」「更长」才看得到变化，
表现正是「设置了好像不生效」。改为先遍历真实取值再合并，空列表才回落默认值。

线上复现旁证：公告 A 当时是 `displaySeconds=60 / pauseSeconds=5`，浏览器算出的
`animation-duration: 65s`、关键帧 `92.3077%` 处停在 -50%，即每轮要等 60 秒才停 5 秒；
再加上列表写着「速度 300 px/s」而实际不参与换算，更容易被判成「没生效」。因此一并把
「填了显示时长」时的速度字样从列表与「实际：…」摘要里去掉。

### ③ 输入可清空 + 预览

- 三个数值参数在草稿里改为**字符串**：受控 `type=number` 若在删空那一刻回落默认值，
  用户只能从 60 慢慢加减。空串 = 默认值（60 / 2 / 0），提交时由 `draftNumber` 解析，
  绝不会把 0 当速度发出去。
- 抽出 `ui/src/components/announcement-ticker.tsx`：测量、重复份数、paced 关键帧、拖动都
  收敛到这一处，顶栏与管理页预览共用，避免「预览好看、顶栏不对」。预览展示当前草稿
  （标题、正文、级别、三个参数）的单行滚动效果，悬停暂停；内容为空时给占位提示。
- 预览踩到一个正反馈：`repeat` 由「可视区宽度 ÷ 一份内容宽度」决定，而弹窗里的预览容器
  宽度又由内容决定，于是「撑宽 → 多重复几份 → 更宽」，实测 viewport 被撑到 41 万像素、
  轨道渲染 7000 多份，弹窗直接卡死。两处收口：预览容器 `w-full` + 弹窗内容列 `min-w-0`
  （DialogContent 是 grid，默认 `min-width: auto` 会被内容撑开），测量端再把可视区宽度
  夹到 `window.innerWidth`（可视区不可能比窗口更宽）。

### 验证

- 后端新增 `标题与内容都空` 的 400 用例；`TestCreateAnnouncementWithoutTitle` 仍通过；
- `announcement-scroll.test.ts`：单条公告的速度/停留不被默认值盖掉；
- `announcement-management.test.tsx`：清空后重输、清空保存回落默认、正文为空时禁用保存并提示、
  弹窗里有预览；
- `announcement-bar.test.tsx`：原有 21 条（速度换算、停留时长、多行拼接）全部通过；
- 浏览器实测（127.0.0.1:8080，super 账号）：
  - 顶栏公告 `paced / 100 px/s / 停留 3 s / 显示时长留空` → `animation-duration: 18s`、
    关键帧 `announcement-scroll-paced-833333`；每 0.5 s 采样 transform，尾部连续 6 个样本
    （约 3 s）不动，即停留真实生效；
  - 弹窗预览同一份草稿，viewport 638 px、重复 24 份、`animation-duration` 随输入即时变化
    （速度 120 + 停留 7 → 22 s = 15 s 滚动 + 7 s 停留）；
  - 速度/停留输入框可清空并重新输入，空正文时保存按钮禁用且出现「内容不能为空」提示；
  - API：`POST` 标题与正文都空 → `400 标题和内容不能同时为空`；
  - 验证后已把线上公告恢复为验证前的参数（300 px/s / 停留 5 s / 一轮 60 s）。
