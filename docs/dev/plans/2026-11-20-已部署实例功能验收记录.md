## 0. 怎么用它做增量检测

1. 每轮测试只在本文件追加「第 N 轮」小节，**不要覆盖**历史结论；缺陷只在「缺陷台账」里改状态。
2. 复跑某功能面时，先看它的「状态」列：`待测` / `通过` / `失败(缺陷ID)` / `阻塞(原因)` / `不适用(依据)`。
3. 增量对比方法：本轮改动涉及 §7「改动面 → 必测用例」映射的，只跑映射到的用例；发布前再跑一遍完整「功能面矩阵」。
4. 密码、API Key、Secret 一律不写进本文件；测试账号口令登记在被 git 忽略的 `.local/ui-test-accounts.md`。
5. 每轮开跑前先核对 §1 的基线项。**特别注意**：本实例的 `/api/v1/version` 来自 `Makefile.local` 写死的覆盖值，**不能用来判断代码新旧**；要确认被测代码，看 `bin/aerolink-e2e` 的构建时戳与 `git rev-parse HEAD`，必要时 `make build` 后重启进程。

### 3.1 第 2 轮取证方式与限制

IDE 内嵌 Chromium 视图处于隐藏态（`document.visibilityState=hidden`），`take_screenshot` 与受信任真实点击受限，因此：

- 失败项证据用 **DOM / a11y 原文 + 接口响应**替代截图，本轮 0 张截图。
- 下载类核对改为 hook `URL.createObjectURL` 取 blob 文本 + 直接 GET 下载接口做**字节级**比对。
- 上传用 `DataTransfer` 注入 `File` 触发真实 `onChange`，容器内 `sha256sum` 回查。
- **D-27（toast 不消失）定性存疑**：很可能只是隐藏视图下 rAF/动画不执行，需在人眼可见的窗口复测后再定级。

### 3.2 第 3 轮阻塞说明

浏览器在内嵌视图下被一个**原生 `confirm` 对话框**硬阻塞（删「权限绑定」的确认框），所有 CDP 指令超时，第四部分 `uitest-view01` 的 fail-closed 用例与第五部分（审计检索/导出、系统日志、API 密钥、通知/模板/导航）因此未执行。

事后用 API 只读核实（`GET /api/v1/admin/binding-groups/?cluster=devops-wxh`）：那个删除**并未生效**，现场无损坏：

- `ui-smoke-editor-binding`（`devops-wxh` / `ui-smoke`）仍在，成员 `uitest-dev01`、`uitest-multi01` → 角色 `ui-smoke-editor`。
- `uitest-admin01` 已在「管理员」绑定组里拿到 `admin` 角色。
- `uitest-view01` **零绑定**（`ui-smoke-viewer` 角色已建但未绑到命名空间）——补绑时要注意**一个命名空间只能属于一个绑定组**，得先把 `ui-smoke` 从 editor 绑定里挪走，或者另建一个命名空间给只读账号用。

## 18. 专项实测：多人同时查日志 / 同时进同一个 Pod 的终端

脚本：`.local/ws_concurrency_test.py`（日志）、`.local/ws_term_concurrent.py`（终端，手写最小 WS 客户端，含 Origin 头与 ping→pong 应答）。三个账号各用各的会话（同账号是单会话，会互相顶掉）。

### 代码结论

两条链路都**没有服务端并发上限**：每个 WebSocket 连接各自建一条 `BatchLogHandler`（`pkg/resources/logs_handler.go`）或一条独立的 kubelet exec 会话（`pkg/terminal/terminal_handler.go` → `kube.NewTerminalSession`），鉴权都在**升级之前**完成（`pods/log` / `pods/exec`）。

### 实测结果

| 场景 | 结果 |
| --- | --- |
| 三人同时看 `ui-smoke/ui-smoke-stream` 的日志，各 15 秒 | 每人 **109 帧**、seq 区间都是 **27774→27881**，完全一致，**0 个错误帧** → 并行无干扰、无丢行 |
| 三人同时进同一容器终端 | 三个都 `101`；`tty` 分别是 **/dev/pts/0、/dev/pts/1、/dev/pts/2**；各自的 `MARK-FAST-*` 与 `sleep 7` 后的 `MARK-SLOW-*` 都完整回显，彼此看不到对方的输入 → **各自独立的会话** |

**答复：支持。多人可以同时查询同一个 Pod 的日志，也可以同时进入同一个 Pod 的终端，互不串扰。**

### 但有三点必须知道

1. **同账号不能两人共用**：单会话策略下后来者会顶掉前者（被顶会话的 API 返回 `401 {"code":"session_superseded"}`，并给管理员发 `session_takeover` 通知）。协作必须各用各的账号。
2. **没有并发配额**（记为 **D-55**，中）：N 个人看同一个 Pod 就是 N 条到 kubelet 的 follow 流，N 个人开终端就是 N 条 exec 流，全部经 apiserver proxy。批次 2 加的 20000 行上限是**每个会话**自己的缓冲，不封顶总并发数。人多了会同时抬高 AeroLink、apiserver、kubelet 三处的连接与内存，目前既没有限流也没有指标/告警。
3. **容器内是同一个世界**（记为 **D-56**，低）：终端会话彼此独立，但共享容器的文件系统与进程空间——一人 `rm`、`kill` 会立刻影响其他人的现场；界面也没有「当前还有谁在这个 Pod 里」的在场提示。属于协作风险提示，不是平台缺陷。

另外记录一条设计说明：日志与终端走裸 WebSocket，**不经过 api-client**，因此不参与「写操作二次确认」与 MFA step-up 的请求拦截（`pkg/wsutil` 与 `lib/write-confirm.ts` 的注释都写明了这个边界）。

### 20.2 D-57（高）：编辑页保存仍然会静默覆盖他人的修改——D-28 的修复在这条主路径上被绕过

复现（第 9 轮）：Deployment/ConfigMap 编辑页的「编辑 YAML 并创建」，其 YAML 是**由上方表单生成**的，
其中**不含 `metadata.resourceVersion`**。流程「B 打开 → A 改并保存 → B 保存」里，B 的 apply 因为不带 RV
而是**无条件覆盖**：HTTP 200，没有 409，也没有中文冲突提示，A 的改动被无声抹掉。

也就是说：D-28 / D-29 修的是「客户端带了 RV 时不要丢掉、冲突要如实上报」，但界面这条最常用
的路径压根不带 RV，所以乐观锁在 UI 层等于没启用。修法待定（两个方向：生成 YAML 时带上实时
RV；或 apply 前按 name 拉一次最新对象比对 RV，不一致就拒收并提示刷新）。

同时暴露 **D-58**：类型化 **PATCH** 路径的冲突仍是 `HTTP 500` + k8s 英文原文
（`Operation cannot be fulfilled on configmaps "ui-regress-cm": the object has been modified; ...`），
D-29 的 409 改造只覆盖了 apply 与 PUT，PATCH 是第三条路径。

### 20.3 D-63：NetworkPolicies 在侧边栏出现两处（已修 + 已验证）

根因（不在 NetworkPolicies 本身，而在侧边栏配置的迁移补录）：

- `ensureDefaultEntries()` 判断「这条菜单是否已存在」**只看当前分组**；
- `removeStaleEntries()` 判断「这条是否已废弃」看的是**全局 URL**；
- 于是只要某个条目的实际归属与 `resourceCatalog` 里的 `sidebar.groupKey` 不一致，
  补录就会在默认分组**再补一份**，同一个菜单出现两个入口。

本机 `general_settings.global_sidebar_preference`（v6）里命中 **7 个**：
`/networkpolicies`（默认「流量」/ 实际「安全」）、`/horizontalpodautoscalers`、`/poddisruptionbudgets`
（默认「配置」/ 实际「集群基础设施」）、`/persistentvolumes`、`/storageclasses`
（默认「集群基础设施」/ 实际「存储」）、`/limitranges`、`/resourcequotas`（默认「其他」/ 实际「集群」）。
后端 `applyBootstrapSidebarPreference()` 会把**全局**布局注入给没有个人偏好的账号，
所以这不是个别账号的问题。

修复：把两处存在性判断都改成**按 URL 全局去重**（已在任一分组就不再补录；整组缺失时也只补真正新增的）。
归属保持存量配置里的位置，不擅自搬到默认分组。

曾考虑再加一层「默认分组变了就把条目搬过去」，判据是用 `id` 前缀是否等于所在分组来区分
「用户手动挪过」与「默认搬家」。查实际数据后**否掉了**：7 个条目的 id 前缀**全都**等于当前默认分组，
说明这个信号并不能证明是用户挪动（历史迁移同样会产生这种形态），据此搬动属于臆测，故不实现。

验证：`ui/src/contexts/sidebar-config-defaults.test.ts` 新增 3 条（只出现一次且保持原归属 /
重复迁移幂等 / 整组缺失也不补第二份），vitest 6 passed；重建 `static/` 并重启后，界面逐分组核对
**7 项各只出现 1 次**，「自定义侧边栏」对话框内也无重复，控制台无侧边栏相关报错。
注意：改动在页面**加载时**生效，旧会话需刷新一次。

  **明文登录照常接受**（加密是客户端可选，不构成强制）；**非法信封 400 显式失败**（fail-closed 成立）。

  **不继承创建者角色**（`Admin role required` / `user <key> does not have permission …`），

  删除后旧密钥立刻 401；受限账号不能自建密钥（403）。
- **MFA 全链**（uitest-multi01）：setup 需当前口令证明本人，**口令错 → 400**；
  **错码不能启用**；启用后登录缺码 `401 mfa_required`、错码 `401 invalid_mfa_code`、
  正确码 204；关闭必须提交当前有效码，关闭后回到只需口令 —— 每一步都 fail-closed。

**step-up（`RequireMFAStepUp`，保护已存 kubeconfig）主链 C12/C10 两条 FAIL 都不是缺陷：**
① 本实例 `security_setting.mfaStepUpEnabled = **false**`（`mfaPolicy=disabled`），门槛整条形同关闭；
② 即便打开，**用动态码登录成功时 `login_handler.go:328` 就调了 `MarkTrusted`**，
同一浏览器（带 `aerolink_mfa_trust` cookie）在 `mfaVerifyTtlSeconds` 窗口内直接放行。
于是构造真正会被拦的情形（`.local/r20b_stepup_enforce.py`）：临时打开开关 → 给 admin01 绑定 MFA
→ 动态码登录（带 trust 时 200）→ **只摘掉 trust cookie** → kubeconfig **403
`mfa_verification_required`** → `/me/mfa/verify` 换 step-up 后 200 读到 kubeconfig → 收尾。
影响面评估写在脚本开头：`mfaStepUpRequired` 第一步就是 `!user.MFAEnabled → false`，
而当时**没有任何账号绑着 MFA**，所以临时开这个开关对其它账号无感 —— 这是我敢动全局安全设置的前提。
**但我在这里踩了一个必须记下来的坑**：还原用的 PUT 走的是链路早期的会话，那个会话已经
**401** 了，还原被静默跳过，`mfaStepUpEnabled` 留在 `True`。发现后立即重登补做还原，
并与改动前保存的全量原值**逐字段比对确认一致**；脚本也修成「还原前独立重登 + 断言 PUT 状态码 +
再 GET 比对」。这条已单独记入长期记忆。

**安全设置页本身（只读抄录，全程未保存）**：5 个页签（认证安全 / 登录限制 / 密码安全 /

## 36. 第 21 轮：边界与性能（D-165、D-171、D-172）

素材构造法记下来，下次别再绕：**1000 行的表格不必创建 1000 个对象** ——
建一个 **1000 个 data 键的 ConfigMap**（46.1 KiB）就能制造 1000 行详情表格；
超长日志用一个 Deployment 在容器启动时打印 `3×300KB + 1×2MB` 并以 `TAIL-MARKER-DONE` 结尾。
自己犯的两个契约错也记下来：`POST /api/v1/resources/apply` 的请求体是
**`{"yaml": "<字符串>"}`**，我按 JSON 对象直接发，被 binding 校验 400（`Field validation for 'YAML' failed`）；
日志**只有 WS 路由**（`/api/v1/logs/:namespace/:podName/ws`），没有 REST GET。

### 36.3 差点误报与已澄清（本轮两条）

- 子代理报「ConfigMaps **列表页**把 1000 个键名全量内联进一个单元格，属过度显示」——
  **误报**。`data-keys-cell.tsx` 是 `max-w-72 … truncate` + 完整列表放 tooltip +
  `resourceTable.keyCount`，设计上就是只显示一行；它读到的是**隐藏 tooltip 的 DOM 文本**。
  这是「DOM innerText 不等于用户所见」的又一例，与第 16 轮 `[Kite]` 前缀那次同类。
- 「超长日志下载得到 1.53 MiB 文件」曾被当成前端截断的证据 —— 实际 `downloadLogs` 是
  `model.getValue()` → `Blob` 的**纯本地**动作，无网络请求，它下载的正是已经收到的不完整内容，
  所以它只能证明「前端拿到多少」，不能证明「谁截断的」。
