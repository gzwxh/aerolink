# 帮助文档入口与文档站镜像

日期：2026-10-19

## 背景

`docs/` 下这套 VitePress 站一直只作为仓库内文档存在：`make docs-dev` / `make docs-build`
能在本地构建，CI（`.github/workflows/docs-ci.yml`）只在 PR 时校验，既没有托管方式，控制台里
也没有任何通往文档的入口（`ui/src` 里搜不到相关链接）。同时站点内容仍留着上游口径：
sitemap 指向上游域名、head 注入 `cloud.umami.is` 埋点、首页与主题挂 GitHub star 与社区外链。

目标是让文档站能独立部署并可从控制台直接打开，且部署形态不依赖公网。

## 设计

### 一、文档站镜像（独立于应用镜像）

单二进制是应用侧的既定前提（`static/` 由 Go embed），root `.dockerignore` 明确排除 `docs`，
因此文档站**不并入应用镜像**，单独出一个 nginx 静态镜像：

- `docs/Dockerfile`：多阶段，`node:24-alpine` 构建 → `nginx` 托管 `/usr/share/nginx/html`，
  容器内监听 80。
- `docs/.dockerignore`：构建上下文取 `docs/` 本身（`docs/` 自包含），排除 `node_modules`、
  `.vitepress/dist`、`.vitepress/cache`、内部工程文档 `dev/` 与本地备份。
- `Makefile` 新增 `docs-image` 目标，变量 `DOCS_IMAGE` / `DOCS_NGINX_IMAGE` / `DOCS_NPM_REGISTRY`
  与既有 `image` 目标同风格。
- 两个基镜像都走公司 SWR，与主 `Dockerfile` 约定一致。

构建期三个约束（均已实测）：

1. 仓库里的 `docs/pnpm-workspace.yaml` 是占位文本，pnpm 10+ 会以 `ERR_PNPM_IGNORED_BUILDS`
   拒绝安装 → 必须在 `COPY . .` **之后**覆盖成明确决策再 `pnpm install`。
2. 不能调 `pnpm run docs:build`（它是 `git fetch --unshallow || vitepress build .`），
   直接 `pnpm exec vitepress build .`。
3. `lastUpdated` 会对每页 spawn `git`，容器里没有 git 也没有 `.git` 历史，实测构建中断
   （`spawn git ENOENT`）；给构建阶段装 git 也不可行（alpine CDN 不可达）→ 用
   `DOCS_SKIP_LAST_UPDATED` 环境变量显式关掉（`config.mts` 读该变量）。

另：从 `docs/public/` COPY 进来的静态文件权限跟着检出时的 umask 走，可能是 `0600`，
nginx worker 非 root 会 403，因此最终阶段 `chmod -R a+rX`。

### 二、站点去外呼

站点面向不特定访问者，且部署环境可能不能出公网，因此清掉全部外部依赖：

- `config.mts`：删除 head 里的 umami 埋点；`sitemap.hostname` 改成本站域名；
  删除 `socialLinks` 的 GitHub 链接。
- `theme/components/AeroLinkHome.vue`：删除 GitHub star 组件与社区/GitHub 外链入口。
- 删除 `theme/components/GitHubStarCount.vue`。
- 页面正文里的可点击外链改成纯文字：`guide/global-search`（上游源码裸 URL → 改指仓库内
  路径）、`faq`（Issue / Slack / GitHub 入口）、`config/prometheus-setup`（上游 chart 与
  组件链接）、`config/rbac-config`（DEX 链接），中英同步。
- 两类「命中域名但不是外呼」的内容保留：构建产物里 `focus-trap`/`tabbable` 的
  `@license MIT, https://github.com/…` 许可注释（MIT 归属要求，删了反而违约）、
  `docs/dev/**` 里的依赖名与工程记录（`srcExclude` 已排除，不进站点）。
- `editLink` 保留（指向内网 GitLab，非外呼）。

### 三、帮助文档地址（可配置）

地址由管理员在「系统设置 → 通用」填写，随公开的 bootstrap 接口下发，因此**登录页也能打开**。

- 数据：`general_settings.help_url`（`varchar(500)`，可空）。
  该表不属于 `internal/config.go` 的托管章节（`ManagedSections` 只有
  `clusters/oauth/ldap/rbac/superUser`），所以天然是「界面可写、库中持久化」。
- 读写：复用既有 `GET/PUT /api/v1/admin/general-setting/`（`routes.go`），
  门禁 `RequireSettingsSection(general)` 不变。
- 校验：只接受 `http(s)` 且带 host 的绝对地址，或空串；长度 ≤ 500 字符。
  其它 scheme（`javascript:`、`data:`）一律 400——这个值会被下发给未登录页面并渲染成外链。
- 下发：`bootstrapResponse.branding.helpUrl`。

### 四、界面入口

- 设置页：新增「帮助文档」块（输入框 + 保存后生效说明 + 「打开文档」按钮），
  与「品牌」块同风格，只读章节禁用。
- 顶部导航栏：两个快捷按钮，配置了地址才渲染（避免出现必然打不开的入口）。
- 登录页：配置了地址时在页脚区域显示入口。

## 库结构变更

`pkg/model/general_setting.go` 新增列，需要人工执行的升级动作。三库等价写法：

```sql
-- MySQL 5.7 / 8.x 与 SQLite 通用；重复执行在 MySQL 上报 1060 Duplicate column name，可忽略
ALTER TABLE general_settings ADD COLUMN help_url VARCHAR(500);

-- PostgreSQL 幂等写法（推荐）
ALTER TABLE general_settings ADD COLUMN IF NOT EXISTS help_url varchar(500);
```

PostgreSQL 需以表 owner 身份执行（应用账号执行会报 42501）；`AutoMigrate` 只做告警不阻断，
所以不能指望启动时长出来。

未执行的后果不发散：读路径 `DB.First` 是 `SELECT *`，缺列不报错，只是地址恒为空（入口不显示）；
写路径 `Updates(map{"help_url": …})` 报列不存在，保存通用设置返回 500。

发版时要抄进发布说明（`docs/dev/release-checklist.md` §1.1），面向运维的升级步骤在
`docs/guide/installation.md` 的「升级」一节（中英同步）——解除重复维护，SQL 以本节为准。

执行后核对：

```sql
SELECT column_name, data_type, character_maximum_length
FROM information_schema.columns
WHERE table_name = 'general_settings' AND column_name = 'help_url';
```

## 影响面

- nginx 基座是 Debian 版（`nginx:1.31.7`），镜像约 282MB；换 `-alpine` 可压到约 60MB。
- 站点「最后更新」时间在容器构建产物中不显示（无 git 历史），本地/CI 构建不受影响。
- 新增设置项不改变既有鉴权与 RBAC 路径；`helpUrl` 属于公开信息，不泄漏集群数据。

## 验收

1. `make docs-image` 构建成功；容器在 80 端口可访问，产物内 grep 不到任何外部域名。
2. `go test ./pkg/settings/... ./pkg/model/...` 通过；未配置时 `helpUrl` 为空串。
3. `pnpm --dir ui exec tsc --noEmit -p tsconfig.app.json` 通过。
4. 管填写非 http(s) 地址 → 400；填写后登录页与顶栏都能打开。
