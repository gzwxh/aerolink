# 图表系列色收敛整改方案（2026-10-19）

- 状态：**已实施**（2026-10-19，改动与复算结果见 §七「执行记录」；仅剩 §五的人工视觉走查未做）。

## 一、背景与目标

来源：[`2026-09-21-语义状态色token.md`](./2026-09-21-语义状态色token.md) §7.5 补记的遗留项——
`ui/src/styles/themes/*.css` 里 12 套主题的 `--chart-1`…`--chart-5` 只落了「近似隐形」下限
（对卡片 ≥ 1.5）与可见性断言，**「全量 3:1 重刷」一直挂着**，当时定为「单独设计任务」。

判定口径（本方案沿用并收紧）：

- **目标阈值**：WCAG 2.1 SC 1.4.11「非文本对比」——图表系列色属于图形/UI 组件，对**相邻背景**
  至少 **3:1**。图元落在 `--card` 上，故口径为 `chart-i` 对 `--card` ≥ 3。
- **现状下限**：`theme-contrast.test.ts` 已有的「对卡片 ≥ 1.5」断言保留（挡同色退化），
  本方案在它之上补 3:1 断言。
- **可区分性**：5 个系列色之间色相仍要能区分（同一主题内不得退化成同一色相的明度阶梯）。

范围：只改 `ui/src/styles/themes/*.css` 的 `--chart-*`，不动组件、不动其它 token。

## 二、现状实测（2026-10-19）

用与 `theme-contrast.test.ts` 同口径的临时脚本（culori 解析、alpha 合成到卡片、WCAG 相对亮度）
实算 12 套主题 × {light, dark} × `chart-1`…`chart-5` 对各自 `--card` 的对比度：

- **合计 120 个组合，22 个 < 3:1（18%），0 个 < 1.5。**
- 即：当前没有「隐形」色（≥1.5 断言都过），但**近两成的系列色离图形对比线还差**。

### 2.2 成因归类

1. **浅底取亮色**（light 主题里系列色过亮）：default / eye-care 的 chart-4、chart-5，
   notebook 的 chart-4、chart-5，darkmatter 的 chart-2、chart-3，claude 的 chart-2、chart-3。
   多为 Tailwind 色阶里的 300 / 400 档（amber-300、orange-300 之类）。
2. **深底取深色**（dark 主题里系列色过暗）：default / eye-care 的 chart-1（indigo-600 一档），
   clean-slate 的 chart-3/4/5，ocean 的 chart-5（teal-700），indigo / jfrog / nexus / sunset 的 chart-5。
3. **同色相明度贴卡**：clean-slate dark 的 chart-4/5（与 chart-1..3 同 277° 色相、明度压得离卡片太近）。

## 三、整改策略

**只调明度 / 彩度，保持色相**，按成因分别处理：

- 成因 1（浅底亮色）：把亮色**压暗**到恰好过 3:1（约降 0.10~0.15 的 oklch L，或在色阶里下移一档），
  保留原色相与彩度，避免变成灰。
- 成因 2（深底深色）：把深色**抬亮**到过 3:1（约升 0.10~0.18 的 L，或上移一档）。
- 成因 3（同色相贴卡）：给该主题的 5 色**拉开明度阶梯**——同一色相下让 chart-4/5 与 chart-1 的 L 差
  至少 0.18，或直接把 chart-4/5 换成互补色相（clean-slate 本就是单色相主题，可保留单色相但把阶梯陡化）。

每套主题改完后，**5 色之间的 L / 色相差仍要能分辨**（见 §四断言）。

不追求「一次到位」：改色后立即用 §二 的脚本复算，逐个逼近 3:1。

## 四、断言（`theme-contrast.test.ts` 新增）

在既有「对卡片 ≥ 1.5」断言旁，补一条更严的：

```
for (const [name, modes] of Object.entries(themes)) {
  for (const mode of ['light', 'dark'] as const) {
    for (const i of [1, 2, 3, 4, 5]) {
      expect(ratio(modes[mode], `chart-${i}`, 'card'), `${name} ${mode} chart-${i}`)
        .toBeGreaterThanOrEqual(3)
    }
  }
}
```

（具体写法沿用文件里现有的 `ratio` / `loadThemes` 工具，不新造 helper。）

## 五、验收与回归

- **脚本**：复用本次的临时测量脚本，改色后重算，期望 `below3 = 0`。
- **测试**：`pnpm --dir ui exec vitest run src/styles/themes/theme-contrast.test.ts`。
- **视觉**：12 套主题 × 明暗各扫一眼含图表的页面（柱状 / 折线 / 饼），确认系列仍彼此可分、不刺眼、

- **影响面自查**：`grep -rn "chart-" ui/src` 确认没有硬编码色值绕过 token。

## 六、风险与注意

- 调亮 / 调暗可能破坏主题原本的配色协调（尤其 default / eye-care 的系列色直接取自 Tailwind 色阶）
  ——优先在原色相内微调，实在过不了 3:1 再考虑换邻档色。
- 暗色主题的 chart-1 多为深色，抬亮后可能与 chart-4 等靠近 —— 需连带校正色相 / 彩度差，
  不要只抬 L 造成「一片蓝」。
- 本方案只解决「对卡片」的 3:1；若图元落在 `--muted` 等其它底色上，另按需扩展口径，不在本次范围。
