# 方案：注释与工程文档中文化（分批推进）

- 状态：**已完成**（6 个批次全部落地）
- 目标：把仓库里**不含中文的注释**与工程文档正文改成中文，代码、标识符、命令、路径一律不动

## 1. 范围与口径

统计口径：`^\s*(//|#|\*|/\*)` 开头、且**注释正文里没有中文字符**、且正文含 ≥4 个拉丁字母的行。

**不做**：

- `vendor/`（第三方代码）、`static/`（生成物）、`CHANGELOG.md`（生成物）
- `LICENSE`、`licenses/*`（法律文本，需显式评审）
- `README_en.md`、`docs/en/**`、`charts/kite/README.md`（刻意保留的英文版）
- k8s 清单、kubeconfig 等**作为数据输出**的内容（见第 2 节第 2 条）

**已纳入范围**（原为待定，已决定）：

- 脚本打印给开发者看的文本（用法/帮助、提示、进度、错误）：`scripts/*.sh`。例外：
  `scripts/get-version.sh` 的 stdout 是版本号数据（Makefile/CI 消费），一律不动。
- `charts/kite/values.yaml` 里的上游 Helm 脚手架注释：一并中文化（不再保留上游原文）。

## 2. 每批的硬约束

1. **只改注释文本**：不改代码、标识符、字符串、格式。每批用
   `git diff -U0` 逐行核对——新增/删除的行必须都是注释行。
2. **保留英文技术词**：k8s 对象名与字段、API 组、错误码、`_all`、RBAC、CRD、JWT、
   `kube-system` 这类专有名词；函数/变量/文件路径原样。
3. **不新增、不删除注释**，也不借机解释代码（注释变长就说明跑偏了）。
4. 每批跑该批相关的既有检查（Go 包 `gofmt` + `go build`；前端 `tsc` + `eslint`；
   YAML/`sh -n`），确认全绿再进下一批。
5. 每批一次提交，提交信息按约定：`chore(<范围>): 注释中文化（第 N 批：<范围>）`。

## 4. 已决定

- 脚本的控制台文本（用法/帮助、提示、进度、错误）中文化；唯一例外是
  `scripts/get-version.sh` 的 stdout（版本号数据）。
- `charts/kite/values.yaml` 里的上游脚手架注释一并中文化。

> 行数是按「不含中文的注释行」估的上限：实测第一批里 `deploy/` 的 14 行、
> `scripts/` 的部分行其实是**被注释掉的配置或数据**，不属本方案范围，逐批都要先甄别。
>
> 第 5 批（`pkg/`）做完后，剩下的 44 行「不含中文」全部是**注释里的代码/标识符/示例**，
> 例如 `s = SecretString(decrypted)`、`/<group>/<ver>/<res>/_all/watch`、`+optional`，
> 属“保留原样”而非待翻译——即 `pkg/` 的散文注释已 100% 覆盖。全仓库其余目录同理：
> 剩余不含中文的注释行都是代码/标识符/示例，或 `deploy/*.yaml` 里被注释掉的配置。
>

> （版本号数据，Makefile/CI 消费）、`pkg/rbac` 的 `NoAccess()` 报错文案（前端
> `parseRBACError` 按英文原文做 i18n 映射）。
