# 方案：Deployment 详情页「暴露」弹窗对齐 Service 创建表单

- 状态：**已实现**
- 触发：用户指出「暴露」按钮的本质就是新建一个 Service，要求参考 Services 创建页优化那个弹窗。

## 1. 现状

`ui/src/pages/deployment-detail.tsx` 的「暴露」（Expose）弹窗只有三项：Service 类型
（ClusterIP / NodePort / LoadBalancer）、服务端口、目标端口；提交时直接拼一个只有一个端口、
协议固定 TCP 的 `Service` 对象给 `createResource('services', …)`。

而 Services 创建页（`ui/src/pages/service-create-page.tsx` + `ui/src/lib/service-yaml.ts`）支持：
端口名称、端口、目标端口（数字或容器端口名）、NodePort、协议 TCP/UDP、多端口行、会话保持、
选择器编辑，以及一套行内校验（端口范围、targetPort 名字合法性、NodePort 范围）。

两边生成 Service 的路径也不一样：弹窗手拼对象，创建页走 `generateServiceYaml`。同一件事两套实现，
迟早会漂移（比如创建页支持 UDP、端口名，弹窗不支持）。

## 2. 做法

### 2.1 抽出可复用的端口行编辑器

- 新增 `ui/src/components/service-ports-editor.tsx`：把创建页里那段端口行 JSX（名称 / 端口 /
  目标端口 / NodePort（仅 NodePort 类型时显示）/ 协议 / 删除 + 行内错误）抽成受控组件，
  外加「添加端口」按钮。
- 新增 `ui/src/lib/service-yaml.ts` 的 `servicePortErrorCodes(ports, serviceType, nodePortRange)`：
  返回 `Map<行号, 错误码>` 的纯函数（好单测），错误码到文案的映射放在
  `ui/src/hooks/use-service-port-error-text.ts`（那里才知道当前语言与集群范围），
  行内提示与提交前的错误横幅共用同一份措辞。
  `emptyPortRow()` 也放进 `lib/service-yaml.ts`，供初值与「添加端口」共用。
- 创建页改为使用这两者，行为与文案不变；弹窗复用同一份 UI 与校验，不再各写一套。

### 2.2 NodePort 范围统一按集群真实值

创建页原来把 NodePort 硬编码校验成 30000-32767。这与工作负载表单此前修掉的问题同源：
集群改过 `--service-node-port-range` 时会把合法端口标红。因此：

- 把 `knownNodePortRange` 从 `components/editors/deployment-form.ts` 移到
  `ui/src/lib/node-port-range.ts`（纯函数，判定口径见那里的注释：只认后端读到的
  `source: "kube-apiserver"`）。
- 新增 `ui/src/hooks/use-node-port-range.ts`：一处查询（queryKey `['nodeport-range', cluster]`，
  10 分钟 staleTime），返回集群真实范围或 `null`。
- 工作负载的 `PortsEditor`、Service 创建页的端口行、暴露弹窗都改用它；拿不到范围时不做
  NodePort 范围校验（合法性交给 API），只在能拿到时提示范围。

### 2.3 弹窗本身

改成「和创建页同源的 Service 表单」，但只保留与「暴露本工作负载」相关的部分：

| 字段         | 处理                                                                                                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 名称         | 默认工作负载名，可改                                                                                                                                                           |
| Service 类型 | ClusterIP / NodePort / LoadBalancer。**不给 ExternalName**：它是外部 DNS 名的别名，没有选择器，与「暴露本工作负载的 Pod」需求冲突（要建它请去服务页）                          |
| 端口行       | 复用 `ServicePortsEditor`（多端口、名称、目标端口、NodePort、协议、行内校验）                                                                                                  |
| 选择器       | **只读**展示，取 Deployment 的 `spec.selector.matchLabels`。这正是「暴露这个工作负载」的含义；要自定义选择器请去服务页。Deployment 没有 matchLabels 时禁用提交并提示（原行为） |
| 会话保持     | 加上（与创建页一致）                                                                                                                                                           |

其它：

- 生成走 `generateServiceYaml`（与创建页同一条路径），提交走 `applyResource`（与创建页一致：
  同名 Service 已存在时是原地更新，而不是报「已存在」）。
- 草稿保护：按 AGENTS.md，承载可编辑草稿的弹窗，遮罩 / Esc / 关闭按钮三条路径统一走
  `useUnsavedChangesGuard` + `UnsavedChangesConfirmDialog`（照 `clone-resource-dialog.tsx` 的用法），
  避免改了一半被静默丢弃。
- 每次打开重置为「按当前 Deployment 预填」的初值：端口默认取容器声明的第一个端口
  （没有就 80），目标端口同值。

## 3. 不改的部分

- 后端不动：Service 的创建/更新仍走既有 `pkg/resources/apply_handler.go`。
- 创建页的布局与字段顺序不动，只把端口行与校验换成共享实现。
- Deployment 详情页的 Endpoints 卡片、`hasRelatedService` 判断等不动。
