# 命名空间默认值与「全部命名空间」分页加载

## 1. 问题

两个来自实际使用的反馈：

1. 表格默认选中 `default` 命名空间。受限账号（只有部分命名空间权限）一进资源页就打
   `/api/v1/<resource>/default`，后端按 RBAC 拒绝，页面显示「用户 xxx 没有权限在集群
   xxx 的 Namespace default 中查看 xxx」，必须手动切一次命名空间才能用。
2. 选择「全部命名空间」（`_all`）时，前端把整个集群的该资源一次拉完再做客户端分页。
   对象多的大集群上首屏要等很久，期间还带着 5 秒一次的轮询，把集群和平台都拖慢。

## 2. 方案

### 2.1 默认命名空间按权限解析（前端）

- `useResourceTableState` 复用 `useResources('namespaces')`（与命名空间选择器同一个
  query key，不会多打请求）。该列表在后端 `pkg/resources/generic_resource_handler_list.go`
  里已按 `rbac.CanAccessNamespace` 过滤，就是「当前用户能看的命名空间」。
- 没有 `initialNamespace`（URL 显式指定）时，选中值不再写死 `default`：
  - 未选过：命名空间列表里优先 `default`，否则取第一个（列表已按字母序）；
  - 存过但已无权限（权限被回收）：同上回落；
  - 多选里混着无权限的：剔除无权限的，全被剔除则回落；
  - `_all` 是用户显式选择，保持不动。
- 命名空间列表到位之前不发起资源请求（`namespaceReady`），避免先按 `default` 打一次
  必然 403 的请求。列表请求失败（连命名空间列表都不可见）时回落到旧行为。
- URL 里显式指定的命名空间不参与校正：那是用户/链接的显式意图，保持原有「命名空间
  不存在」提示逻辑。

### 2.2 「全部命名空间」增量分页（前端）

- 新增 `usePagedResources`：`_all`（以及集群级资源，如 Nodes）不再一次拉全量，而是带
  `limit=200` 请求第一批，响应里的 `metadata.continue` 存下来；表尾显示「已加载 N 行」
  与「加载更多」，点一次追加下一批。
- 单命名空间（含默认解析出的命名空间）仍走原来的全量请求：数据量通常可控，且保持
  客户端搜索、列筛选、导出的既有语义不变。
- 「刷新 / 轮询」重取的是「已加载条数」而不是全量；首次进入固定 200 条。

### 2.3 后端：分页请求绕过 informer 缓存

`K8sClient` 内嵌的是 controller-runtime 的缓存客户端，它的 `List` **不支持真分页**：
带 `continue` 直接报 `continue list option is not supported by the cache`，带 `limit`
只在本地截断并塞一个假 token `continue-not-supported`（第一次「加载更多」就是死在这里）。

- `kube.K8sClient` 新增 `DirectClient`（`client.New(config)`，不经过缓存）；
  `DISABLE_CACHE=true` 时两者是同一个实例。
- 列表 handler 里 `paginationClient` 按请求选客户端：带 `paginate=true`（前端分页）
  或 `continue` 非空 → 直连；其它只带 `limit` 的既有调用方（命名空间详情、最近事件、
  标签选择器预取等）继续走缓存，保持原来的响应速度与 apiserver 压力。
- 缓存路径的假 token 在返回前抹掉，避免被调用方当成真游标。
- 前端 `fetchResources` 新增 `paginate` 参数，`usePagedResources` 的每次请求都带上它。

### 2.4 已知取舍

- Kubernetes 的 `continue` token 只能顺序向后翻，不能跳页，所以「加载更多」是追加式的，
  跳页仍在已加载范围内进行。
- 服务端 `limit` 在 RBAC 逐项过滤之前生效，一页可能被滤空。`usePagedResources` 会继续
  往后翻（最多 10 次）以凑够一批；权限极小的账号可能首批仍为空，这是「跨命名空间 list +
  平台侧过滤」的固有代价。
- 搜索框与列筛选作用于**已加载**的数据；表尾用「已加载 N 行」而不是「共 N 行」，避免把
  已加载数当成总数。
- Deployment 列表页的「重启次数」列改为只在选中单个命名空间时按 Pod 汇总；「全部 / 多选」
  视图下该列留空（原来要拉全集群 Pod，是首屏慢的主因之一）。
- CR 列表（`crs`）与 Nodes 的自定义 handler 尚未接入真分页，仍按原逻辑返回，前端只是拿不到
  `continue`、不会报错。

## 3. 验证

- `pnpm --dir ui exec tsc --noEmit -p tsconfig.app.json`
- `pnpm --dir ui exec vitest run src/hooks/use-resource-table-state.test.ts
  src/hooks/use-paged-resources.test.ts src/components/resource-table.test.tsx`
- `go test ./pkg/resources ./pkg/kube ./pkg/cluster`
- 手工核对：受限账号进入 `/deployments` 默认落在有权限的命名空间，不再出现 403；
  `_all` 首屏只发一次 `limit=200&paginate=true` 的请求，表尾「加载更多」能继续翻页。
