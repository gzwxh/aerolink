# 集群信息进入浏览器地址栏（`/_clusters/<slug>` 全站前缀）

## 0. 背景与目标

现状：平台管理多套 K8s 集群，但浏览器地址栏里的路径**不带集群信息**
（`https://aerolink.gcongo.cn/deployments/onebuy-gz-pt/onebuy-gz-man-api-pt`）。研发把
链接发给运维时，运维在浏览器里看不到这是哪套集群，必须先登录、再看顶栏的集群徽章/切换器
才能确认——而「先登录再确认」这件事本身就带着看错集群、在错误集群上操作的风险。

目标：把**集群标识放进 URL 路径**，做到「拿到地址就知道是哪套集群」，并且链接可分享、
可直接深链打开、可被书签收藏。

已确认的三个前置决策（本次方案的边界）：

1. URL 形态采用**路径前缀** `/_clusters/<cluster>/<原路径>`。
2. 集群段用**受限字符集的安全短名 slug**，由系统在配置/导入集群时**自动生成**并存库，
   多套集群之间保证唯一、不冲突（创建时也可手填覆盖）；不做「集群原名百分号编码进路径」。
3. 前缀**覆盖全站**（含设置页、账号、独立 AI 页），只有登录/初始化例外。
4. slug 在创建时固化，此后不随集群改名变化。

## 1. 现状盘点（证据）

### 1.1 集群身份当前只在「存储」里，与地址栏无关

- 唯一事实源是 `ui/src/lib/current-cluster.ts` 的 `getCurrentCluster()`（读
  `sessionStorage`/`localStorage` 的 `current-cluster`）；`setCurrentCluster()` 写入。
- 集群归属的产生方式（**全部来自存储值，不来自 URL**）：
  - 普通 API：请求头 `x-cluster-name`（`ui/src/lib/api-client.ts` 的
    `appendCurrentClusterHeader`，值经 `encodeURIComponent`）；
  - SSE / WebSocket：查询参数 `x-cluster-name`（同文件的 `appendCurrentClusterParam`，
    因为 WS 设不了请求头）；
  - 少量需要「URL 自带集群」的链路：`withCurrentClusterPath()` 拼出
    `/api/v1/_clusters/<encoded>/...`，用于 Pod 文件（`ui/src/lib/api/core.ts:1271/1287/1303/1323`）、
    通用资源取数（`ui/src/lib/api/core.ts:1198`）、端口代理 iframe
    （`ui/src/components/service-overview.tsx:319`、`pod-overview-sidebar.tsx:204`）。
- 后端侧：`routes.go:335` 注册了 `api.Group("/_clusters/:cluster")`，`pkg/middleware/cluster.go`
  的 `ClusterMiddleware` 按「路径参数 → 请求头 → 查询参数」的顺序取集群；
  `DecodeClusterName` 负责还原 URL 编码（注释里写明「HTTP 头只能带 ASCII」，所以集群名
  必须编码——这正是**集群名不能裸放进路径**的原因）。

### 1.2 浏览器路由是扁平的

`ui/src/routes.tsx` 用 `createBrowserRouter`，`basename` 取 `getSubPath()`
（`ui/src/lib/subpath.ts`，由 `AEROLINK_BASE` 决定子路径部署）。所有业务路由都没有集群段。

`static.go:48` 的 `NoRoute` 对除 `base+/api/`、`base+/assets/` 之外的一切路径都返回
`index.html`。**因此新增任意深度的前端路径都不需要改服务端路由**（利好，但要保证不占
`/assets`、`/api` 这两个前缀）。

### 1.3 集群名不是安全字符集

- 集群名来自 kubeconfig 的 context name（`pkg/cluster` 的导入链路）。`CreateCluster` 与
  `ImportClustersFromKubeconfig` 只校验「非空 + 不重名」，对字符集没有限制：中文、空格、
  `@`、`:` 都会出现，`/` 在 AWS/GKE 的 context 名里也很常见。
- 现网依赖 `encodeURIComponent` + 请求头这条路走通。放进**路径段**时 `%2F` 会被浏览器、
  网关与 gin 做归一化，**无法可靠往返**；所以路径段必须用 slug。

### 1.4 已有「按路径段位置解析」的代码（前缀会打乱）

- `ui/src/contexts/cluster-context.tsx:42` `clusterSwitchFallback()` 按
  `segments[0]`/`segments[1]` 判断切集群后应回退到哪一页。
- `ui/src/components/dynamic-breadcrumb.tsx` 按段位置生成面包屑，且 href 是绝对路径：
  `pathSegments[0]`（第 24、69 行）、`pathSegments.length === 3` 判命名空间（第 76 行）、
  `/${pathSegments.slice(0, index + 1).join('/')}` 拼链接（第 78 行）、`<Link to={crumb.href}>`
  （第 118 行）。加前缀后既会多出一个 `_clusters` 面包屑，又会拼出**丢前缀**的链接。
- `ui/src/components/app-sidebar.tsx`：`isActive()`（第 197-205 行，`startsWith(url)`，且
  `url === '/'` 时要求 `pathname === '/'`）→ 加前缀后概览以外的入口**会全部不高亮**；
  `startsWith('/settings')` 出现在第 184、379、400、433、439 行（决定「设置页隐藏业务导航」、
  自动展开章节、设置子页签高亮）；导航项直接 `<Link to={item.url}>`（第 257、282、389 行）。
- `ui/src/components/site-header.tsx:60` `location.pathname.startsWith('/settings')` 与
  第 63 行 `navigate('/')`（设置页左上角的回首页按钮）同款问题。
- `ui/src/contexts/ai-chat-context.tsx` 用 `path === '/' | '/dashboard' | '/ai-chat-box'`

- `ui/src/lib/write-confirm.ts` 的 `classifyWriteOperation()` / `parseWriteTarget()`：

  本次会顺手修掉（它和本次改动属于同一类问题：路径前缀破坏位置解析）。

## 2. 风险与必须守住的不变式（先看这一节）

原始诉求只说要「地址栏能看出集群」，实现里真正的危险不是改多少文件，而是**集群身份的
事实源从「存储」换成「URL」之后的一致性**。以下四条是硬约束，落地方案围绕它们组织。

### 2.1 风险清单（按严重程度）

| # | 风险 | 后果 | 对策（见 §3.3） |
| --- | --- | --- | --- |
| R1 | **深链打开瞬间用错误的集群发请求**：所有请求的集群来自 `getCurrentCluster()`（存储）。别人发来 `/_clusters/prod/...`，运维本地存储还停在 `dev`，首屏的列表/watch/统计会先按 `dev` 发出，而地址栏显示的是 `prod`。 | 在错误的集群上误删/误改。**最高危**。 | I1 + I2 |
| R2 | **URL 与存储/请求头分叉**：浏览器前进/后退、手动改地址栏都不会走 `setCurrentCluster()`，于是不会失效查询缓存，页面（URL）与实际取数集群不一致。 | 显示 A 集群的残留数据、操作打到 B 集群。 | I3 + I4 |
| R3 | **未知/无权限集群静默回落默认集群**：分享链接指向对方无权访问的集群时，若自动跳到「我的默认集群」，运维会以为在看目标集群。 | 误操作 + 排障被误导。 | I2 |
| R4 | **位置解析全部错位**：§1.4 那些按段位置判断的代码会把 `_clusters`/slug 当成业务段。 | 侧边栏不高亮、面包屑多一段、切集群回退到错误页、设置页判断失效。 | §3.5 |
| R5 | **服务端存的 URL 失效**：侧边栏偏好（`users.sidebar_preference`、`general_settings.global_sidebar_preference`）与默认配置里存的是无前缀路径（`/deployments`、`/crds/<name>`）。 | 所有用户的自定义导航点不通。 | §3.6 |
| R6 | **iframe 模式漏带集群**：`App.tsx:65` 的 `?iframe=true` 与代理弹窗的 `src` 若不带前缀，弹窗内按存储集群取数。 | 弹窗内容与所在页面不同集群。 | §3.6 |
| R7 | **应用内前进/后退跨集群**：`ui/src/contexts/navigation-context.tsx` 自维护 pathname 栈（sessionStorage）。带前缀后栈里会混着不同集群的条目。 | 后退到别的集群时当前集群没跟着切（R2 的变体）。 | I4 |
| R8 | **旧链接/书签失效**：无前缀的 `/deployments/ns/name` 是现网正在被分享的形态。 | 分享链接触 404 或空白。 | §3.7 |
| R9 | **slug 生成与唯一性的坑**：加列时若给 `default ''` / `not null`，多行空值会让唯一索引建不起来；集群改名/重导时若重算 slug，已分享链接失效。 | 迁移失败或链接失效。 | §3.2 |
| R10 | **全中文集群名的 slug 可读性**：纯中文名 slugify 后只能是 `cluster`/`cluster-2`，达不到「看地址就知道」的初衷。 | 体验不达预期（非安全问题）。 | §7 未决问题 1 |
| R11 | **e2e 全量失效** | 无法回归。 | §5 |
| R12 | **URL 泄露集群名** | 浏览器历史/代理日志/截图可见（内网可接受）。 | 记为已知取舍，slug 可用非敏感短名 |

### 2.2 必须守住的不变式

- **I1（首帧正确）**：打开 `/_clusters/<slug>/...` 时，**任何集群作用域请求发出之前**
  `getCurrentCluster()` 必须已经等于该 slug 对应的集群名。不能只在 `useEffect` 里「补同步」。
- **I2（fail-closed）**：slug 解析不出（不存在 / 无权 / 已删除 / 拼错）→ 渲染明确的
  「集群不可用」错误页，**绝不**自动回落到默认或上次集群；错误页上给一个显式按钮
  「切换到 <默认集群>」，由人确认。
- **I3（单一事实源）**：URL 是集群归属的唯一源。「当前集群」只允许由「导航到新 slug」
  改变——现存 3 处直接 `setCurrentCluster(cluster.name)` 的调用点
  （`ui/src/components/cluster-selector.tsx:119`、`ui/src/components/global-search.tsx:307`、
  `ui/src/components/settings/cluster-management.tsx:301`）全部改成「导航到同页面的新 slug」。
  请求头/查询参数永远从这一个值派生，不得另立来源。
- **I4（切集群即导航）**：切集群 = `navigate(swapClusterSlug(pathname, newSlug))`，切换后的
  「该页在新集群不适用则退回列表页」规则沿用 `clusterSwitchFallback()`，只是改为在
  **剥离前缀后**的路径上判定；查询缓存的失效以「slug 变化」为触发点。

## 3. 方案

### 3.1 URL 形态与路由结构

```
<base>/login                                  无前缀（登录前还不知道集群）
<base>/setup                                  无前缀（初始化页）
<base>/_clusters/:clusterSlug                 集群作用域的全部页面
<base>/_clusters/:clusterSlug/deployments/onebuy-gz-pt/onebuy-gz-man-api-pt
<base>/_clusters/:clusterSlug/settings/general
<base>/_clusters/:clusterSlug/ai-chat-box
<base>/                                       → 重定向到 /_clusters/<默认或上次>/
<base>/*                                       → 旧链接重定向（见 §3.7）
```

- `basename`（`getSubPath()`）仍是最外层，子路径部署（`AEROLINK_BASE`）不受影响。
- 前缀段固定为 `_clusters`（与后端 API 的 `/_clusters/:cluster` 同名同形，一套心智），
  **不会**与 `settings` / `login` / `crds` / `charts` 这类业务段冲突。
  注意：这与 `ui/src/lib/api/core.ts` 里 `withCurrentClusterPath()` 产出的 API 路径**文本同形
  但内容不同**（API 用编码后的集群名，浏览器用 slug）。这一点要在代码注释与
  feature-code-index 里写清楚，避免后人把两者混用。
- 服务端无需任何改动（`static.go` 的 SPA 兜底已覆盖）。

### 3.2 集群标识：`slug` 的生成、落库与下发

**新增列** `clusters.slug`（`pkg/model/cluster.go`）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `slug` | `varchar(64)`，唯一索引，**可空** | URL 用的稳定短名 |

自动生成规则 `slugifyClusterName(name)`（后端，`CreateCluster` 与
`ImportClustersFromKubeconfig` 两条路径都走，作为「没手填」时的缺省）：

1. 转小写；把 `[^a-z0-9]+` 连续段折成一个 `-`；去掉首尾 `-`；截断到 48 字符
   （留出冲突后缀的空间）。
2. 结果为空（纯中文/纯符号名，如「生产环境」）→ 退化为 `cluster`。
3. 与库里已有 slug 冲突 → 追加 `-<n>`（n 从 2 递增），直到唯一。

**允许手填（已定）**：`POST /admin/clusters/` 的请求体加一个可选 `slug` 字段
（`CreateCluster` 的内联 req 结构体、前端 `ui/src/lib/api/admin.ts` 的 `ClusterCreateRequest`
同步），集群创建表单（`ui/src/components/settings/cluster-dialog.tsx`）里给一个「URL 短名」
输入框，留空就走上面的自动规则。手填时校验 `^[a-z0-9][a-z0-9-]{0,47}$`，重名**直接返回
冲突错误**（不自动加后缀——值是人指定的，静默改写会让人以为生效的是别的值）。
**不引入拼音/转写库**（免新依赖与许可证评审），也**不做**从中文名硬转：中文集群名自动
得到的就是 `cluster` / `cluster-2`，想可读就手填。

**导入时逐行可改（已定，第 1 期）**：`ImportClustersFromKubeconfig` 一次能带多套集群（一份
kubeconfig 的多个 context），所以 `common.ImportClustersRequest` 加 `Slugs map[string]string`
（key = context name）承载逐条指定值：

- **前端解析用已有的 `js-yaml`**（`ui/package.json` 已依赖，无需新增）：新增
  `ui/src/lib/kubeconfig.ts` 解析出 context 列表，导入对话框里逐行渲染「集群名 → URL 短名」，
  预填自动生成值、可改；`cluster-import-dialog.tsx` 的 `onSubmit` 改成 `(config, slugs)`，
  请求体类型在 `ui/src/lib/api/system.ts`（导入接口在 `system.ts`，不在 `admin.ts`）；
  对话框的草稿判定要**把 slug 编辑也算进去**（现在只看 `config` 一个字段），否则改了短名
  Esc 关闭会被静默丢弃；新增文案一律进 `ui/src/i18n/locales/zh.json`（`en.json` 可滞后）。
- **前端的解析只是辅助，不是权威**：YAML 语法错 / 没有 `contexts` 时**不拦提交**，只是不渲染
  逐行列表（提示将按默认规则生成短名），后端照旧解析一次。否则两套解析器口径不一致时会把
  本来能成功的导入挡下来。初始化向导的 in-cluster 模式没有 kubeconfig 文本，同样走自动生成。
- **已存在的集群一律不动 slug**（`GetClusterByName` 命中 → 只更新 config，沿用
  `cluster_manager.go:249` 现有行为），与「slug 创建时固化」一致。设置页拿得到现有列表
  （`useClusterList()`）：这类行直接显示现有 slug、**置灰**并标注「已存在，短名不会改变」；
  初始化向导时库是空的，全是新建。
- **校验 fail-closed、全有或全无**：写库前先把整批校验一遍 —— 逐个匹配
  `^[a-z0-9][a-z0-9-]{0,47}$`、**批内互不重复**、且不与库里**其他**集群的现有 slug 冲突
  （同名集群自己的 slug 不算冲突，因为不动）。任一条不过 → `400` 并指明是哪个 context 的
  哪个值，**一条都不写**。校验抽成 `pkg/cluster/slug.go` 的纯函数由 handler 调用，
  `ImportClustersFromKubeconfig` 因此只是多一个 `slugs` 参数，仍可作包级函数被
  `internal/load.go:67` 调用（那里传 `nil`）。
- 手填值**不自动加后缀、不静默改写**（与人的指定值冲突就报错）；只有自动生成路径做重名去重。

**三条硬约束**：

- **slug 在创建时固化，此后不随集群改名/重新导入变化**（已定）。集群名在第一次配置时就
  确定了；前端编辑表单本来也不提交 `name`（`ClusterUpdateRequest` 是
  `Omit<ClusterCreateRequest, 'name'>`）。后端 `UpdateCluster` 虽然留着 `Name *string` 入口，
  但与 slug 完全解耦——即便改了名，slug 也不重算。已分享的链接优先于 slug 的可读性，
  所以编辑表单里 slug 只读（展示 + 一键复制完整链接）；对应地，前端 `ClusterUpdateRequest`
  的 `Omit` 要同时排除 `'name' | 'slug'`，`UpdateCluster` 的 req 结构体不接收 slug。
- **列可空、不加 `default ''`、不加 `not null`**。`AutoMigrate` 加列后旧行为 NULL；SQLite /
  MySQL / PostgreSQL 的唯一索引都允许多个 NULL，加列不会失败。若给 `default ''` 或
  `not null`，多行空值会让唯一索引创建失败（R9）。
- **回填迁移 `MigrateClusterSlugBackfill`**：幂等（已有非空 slug 的行跳过），排在
  `pkg/model/model.go` 主循环 `AutoMigrate` 之后、`checkSchema()` 之前，注册方式与
  `MigrateBindingGroupMemberNamespace` 一致（`runMigration`，失败只告警不阻断启动）。
  逐行生成 + 全局去重，注意**不要**在循环里对同一 name 生成同一个 slug。

**下发**：`pkg/common/types.go` 的 `ClusterInfo` 加 `Slug` 字段，两个列表接口都要带：

- `GET /api/v1/clusters`（`cluster.ClusterManager.GetClusters`，前端 `ui/src/lib/api/cluster.ts`
  的 `fetchCurrentClusters` / `useCurrentClusterList`，**切换器与本次解析依赖它**）；
- `GET /admin/clusters/`（`ClusterManager.GetClusterList`，前端 `ui/src/lib/api/admin.ts`）。

前端 `ui/src/types/api.ts` 的 `Cluster` 加 `slug: string`。

> `checkSchema()` 会遍历模型字段做只读比对，新增列**自动**被纳入启动自查，无需额外登记。

### 3.3 事实源切换：URL → 当前集群（I1/I2/I3 的落点）

改造 `ui/src/contexts/cluster-context.tsx` 的 `ClusterProvider`：

1. 从 `useParams().clusterSlug` 取 slug（Provider 仍在 `App` 内，`App` 已挂在
   `/_clusters/:clusterSlug` 路由下，所以拿得到）。
2. bootstrap（`refetchClusters()` 之后）里解析 `clusters.find(c => c.slug === slug)`：
   - **解析成功**：先 `persistCurrentCluster(cluster.name)`（同步写存储）→ 同步更新
     state → **最后**才 `setIsLoading(false)`。React 会把这几次 setState 合到同一批，
     子节点渲染时存储里已是正确集群（I1）。
   - **解析失败**：`setError(...)`（新增「集群不可用」错误类型）→ `setIsLoading(false)`，
     由 `ClusterGate` 渲染统一错误页：**中性文案 + 「申请权限」引导 + 「切换到 <默认集群>」

     （`cluster-context.tsx:135-142`）。为什么会有解析失败、文案为什么必须中性，见 §3.7。
3. `setCurrentCluster(name)` 的语义改为 `switchCluster(slug)`：走 `useUnsavedChangesGuard`
   既有的未保存草稿确认（`hasUnsavedEdits()` / `discardUnsavedEdits()` 逻辑保留），确认后
    `navigate(swapClusterSlug(pathname, newSlug))`；切换副作用（`invalidateQueries`
    + `clusterSwitchFallback`）改为由「slug 变化」的 effect 触发（I3/I4）。
4. 无集群上下文页面（`/login`、`/setup`）继续用存储值；`getCurrentCluster()` 的读写接口

#### 为什么会有「无效 slug」，以及怎么处理（已定）

`GET /api/v1/clusters` **已经按权限过滤**（`cluster_handler.go:64` 的
`rbac.CanSeeNamespacesInCluster`），列表内容来自引擎的内存快照（删除 / 停用的集群不在其中，
停用见 `Cluster.Enable`）。所以「slug 解析不出来」的来源有这些，**都是常态而非异常**：

1. 集群被删除或停用 —— 链接还在别人的书签、聊天记录、工单里；
2. 当前账号无权看到该集群 —— 分享场景里最常见的一种（把生产的链接发给了只授权测试集群的人）；
3. 授权被回收 / 绑定组调整后，原本可见的集群变得不可见；
4. 链接被手改、被聊天软件截断、末尾多带了 `）`/`。` 之类；
5. 回填未完成的窗口期（slug 为 NULL，回填后消失）。

**前端无法区分「集群不存在」和「你没权限看它」**：列表接口把两种情况一起过滤掉了，而且
「这个集群存不存在」对无权用户本身就不该泄露。因此错误页：

- 文案中性（「该集群不存在，或你当前无权访问」），**不**显示任何由 URL 反查出来的集群信息
  （不显示名字、不提示它是否存在，避免把 slug 变成集群名的枚举入口）；
- 给两个都由人点击的出口：「申请权限」→ `/settings/rbac?rbacTab=binding-groups`
  （无前缀，正好复用上面的兼容重定向落到默认集群的设置页；能带 `?cluster=<slug>` 更好，
  实现时确认该页是否接受该参数，不接受就只做跳转）；「切换到 <默认集群>」。
- **绝不**自动回落到默认集群或上次集群 —— 那会让运维以为自己在看目标集群（R3）。

### 3.8 明确不做的事（控制影响面）

- 不动业务 API 契约：`routes.go` 的 `/_clusters/:cluster` 分组语义、
  `middleware.ClusterMiddleware`、`x-cluster-name` 请求头/查询参数口径全部不变。唯一的接口
  增量是 admin 侧**可选**入参 `slug`（创建）、`slugs`（导入）与列表出参 `slug`，
  都不影响既有调用方。
- 不让服务端解析 slug：slug 只是**前端导航标识**；集群归属仍由后端按请求头/路径参数判定。
  鉴权、RBAC、审计路径**零改动**（安全边界不动）。
- 不改集群名本身（`name` 仍是 header 传的值、仍是审计与 RBAC 的键）。
- 不做子域方案、不做查询参数方案。

## 7. 决策记录（已定）

1. **中文集群名的 slug**：**不引拼音/转写库，也不从中文名硬转**。自动生成即
   `cluster` / `cluster-2` 这类；同时**允许手填，创建与导入两条路径都要**：创建走
   `POST /admin/clusters/` 的 `slug`，导入走 `POST /admin/clusters/import` 的 `slugs`
   （按 context 逐行，见 §3.2）。不填就用自动值。
2. **slug 无效时**：**统一错误页**（fail-closed），设置页这类全局页也一样，**不**放宽为
   「跳到默认集群的同一页」。理由：R3 —— 静默跳转会让运维以为自己在看目标集群。
   无效的来源与文案口径见 §3.7。
3. **错误页引导**：**加「申请权限」入口**（指向 `/settings/rbac?rbacTab=binding-groups`，
   能带 `?cluster=<slug>` 更好）+ 「切换到 <默认集群>」按钮，两个出口都由人点击。
4. **slug 与集群改名**：**slug 在创建时固化，不随改名变化**。集群名在第一次配置时就已经
   确定，前端编辑表单也不提交 `name`；slug 与 `name` 完全解耦，编辑表单里 slug 只读。

## 11. 收尾：补齐 §9 遗留与 §5 单测（2026-10-16）

§3.2 的两条细节要求、§5 的前端验证清单与手工清单第 8 条的「短名置灰」此前并没有真正
落地，本次一并补齐；补测试的过程里又暴露并修掉一个真实缺陷（见本节第 5 条）。

**（1）初始化向导接入逐行短名（§6「初始化向导同步接入」）**

`initialization.tsx` 原来只提交 `{ config, inCluster }`：在初始化向导里导入一份含中文
context 的 kubeconfig，只能拿后端自动生成的短名（`cluster` / `cluster-2`…），而短名创建
即固化、之后不可改（编辑表单也只读），等于永久失去一个可读的 `/_clusters/<slug>`。
现在向导的粘贴 / 文件模式与导入对话框共用同一个 `ClusterSlugFields`
（`ui/src/components/settings/cluster-slug-fields.tsx`），校验口径、错误提示、「留空即
自动生成」的语义完全一致。

没有把 `ClusterImportDialog` 整体塞进向导，原因有二：向导还有 in-cluster 模式（没有
kubeconfig 文本，短名只能由后端生成，见 §3.2），而它是 modal，嵌进向导的步骤卡片会多出
一条与卡片提交按钮并存的提交路径。共用同一份编辑器代码是「同一套实现」的等价做法。
顺带把对话框里散落的校验/收集逻辑收敛到 `lib/cluster-slug.ts` 的两个纯函数
（`findInvalidSlugContext` / `filledSlugs`），两个调用点不再各写一遍。`filledSlugs` 只
提交「当前 kubeconfig 里仍存在的 context」：粘贴内容改小后再提交，旧 context 的遗留值
不会再被后端算进 slug 冲突判定（`ValidateImportSlugs` 不区分 context 是否真的会被导入）。

**（2）编辑表单的短名只读 + 一键复制完整链接（§3.2）**

`cluster-dialog.tsx` 的编辑态原来整个不显示 slug。现在编辑态展示只读短名 + 「复制」
按钮，复制 `window.location.origin` + subpath + `/_clusters/<slug>`（`copyToClipboard`，
成功/失败走 `common.messages.copied` / `copyFailed`），提示文案
`clusterManagement.dialog.slugReadonlyHint`（zh/en 同步补键）。

**（3）`ClusterUpdateRequest` 从类型上排除 `slug`（§3.2）**

`Omit<ClusterCreateRequest, 'name'>` → `Omit<ClusterCreateRequest, 'name' | 'slug'>`。
后端更新 DTO 本来就不接收该字段，这条只是把「slug 不可改」写进类型，免得以后有人顺手把
表单里的 slug 一起提交上去。

**（4）补 §5 要求的前端单测**

- `ui/src/lib/cluster-path.test.ts`：补/剥/换前缀的纯函数，含两条安全边界——无前缀路径
  原样返回、`_clusters` 不在首段时不算前缀。
- `ui/src/lib/kubeconfig.test.ts`：多 context、中文 context 名、空文本、没有 `contexts`、
  非法 YAML 不抛异常、跳过结构不对的条目。与 §5 原文的差异：**不读 `current-context`**
  ——逐行短名要的是全部 context，只认 current-context 反而会让其它 context 拿不到手填短名。
- `ui/src/contexts/cluster-context.test.tsx`：I1（冷启动深链，子组件的**首个集群作用域
  请求**就带 URL 集群）、I2（未知 slug fail-closed、不回落默认集群、不发请求）、I3
  （切集群后 URL / 存储 / 请求头来源一致）、§3.5（详情页切集群退回列表页、命名空间过滤
  列表保留、顶层列表保留、`useClusterLocation` 剥前缀）。
- `clusterSwitchFallback` / `isActive` / 面包屑没有单独导出可测，回归改成等价的行为断言：
  前者测切集群后的 URL 回退，后两者测它们共同的输入 `useClusterLocation().pathname`。

**（5）补测试时暴露的缺陷：I1 在「子组件先发请求」这一环上其实是假的**

`ClusterProvider` 的集群解析原来写在 `useEffect` 里。`isLoading` 变 `false` 与 `clusters`
落地是同一次提交，子组件正在这次提交里挂载；而 React 的 effect 顺序是「子先父后」，于是
子组件（react-query）的订阅与首个请求先执行，此时 `persistCurrentCluster` 还没发生 ——
**冷启动深链到非默认集群时，首个集群作用域请求不带 `x-cluster-name`**（后端按默认集群
处理，用户先看到的是另一个集群的数据），随后靠 `invalidateQueries` 再拉一次才纠正。
改为 `useLayoutEffect`：布局 effect 在同一提交内、早于任何 passive effect 执行，持久化
先于子组件发请求。I1 的回归测试改之前红、改之后绿。

**（6）导入时对已存在集群的行「短名置灰」（§5 手工清单第 8 条）**

后端的导入是按 context 名匹配的：同名集群走「只更新 config」的分支，短名不参与更新，
用户在手填框里改了半天其实不会被采纳（若填的短名被别人占了才会报 409，更容易被误读成
「改失败」）。现在 `ClusterSlugFields` 接受 `existingSlugs`（集群名 → 已固化短名，
由 `cluster-management.tsx` 从集群列表喂进来），命中这些行时：输入框只读并展示现有短名、
行首加「已存在」标记、组下方给一条说明。这些行同时被排除在校验与提交载荷之外
（`editableContexts`）——集群列表是 5s 轮询的，用户可能在列表到达前先填了一行，过滤掉
才不会带着一个「看起来改了、其实没生效」的值提交上去。

回归测试 `ui/src/components/settings/cluster-import-dialog.test.tsx` 覆盖两种情形：已存在
的行只读且不进载荷；先填后变成已存在的行，旧值被丢弃。
