# 方案：通知订阅新增「全体用户」接收者

- 状态：**已实现**
- 相关：`docs/dev/plans/2026-09-20-console-ux-and-notification-fixes.md`（§5 把投递口径改成「只发给订阅者」）

## 1. 为什么需要它

上一轮把 `SendEvent` 改成「只发给订阅了该事件 + 该渠道的人」之后，订阅成了唯一入口。
而订阅的接收者粒度只有「用户 / 邮箱地址」，于是要「所有员工都收到异地登录提醒」，管理员
必须把每个账号**逐个**加一条订阅；新入职的人还得回来补。现网订阅表是空的 —— 也就是说
安全提醒现在一条都不会发。

用户确认的口径：**加「全体用户」**（按用户组的粒度这次不做）。

## 2. 实现

- `pkg/model/notification.go`：新增接收者类型 `all_users`；新增 `ListEnabledUsers()`
  （只按 `enabled` 过滤，与 `ListAdminUsers` 同一口径）。
- `pkg/notification/service.go` 的 `resolveRecipients`：遇到 `all_users` 时**在投递那一刻**
  展开成当前全部已启用账号 —— 站内信取用户 ID，邮件取有邮箱的账号（没邮箱的跳过）。
  同时按用户 ID 去重：同一个人可能既被「全体用户」命中、又被单独订阅命中，不去重会收到两份。
- `pkg/notification/handler.go`：创建订阅时接受 `receiverType=all_users`，并把
  `receiverId` / `receiver` 强制清空（不绑定具体账号）；未知类型仍然被拒。
- 前端：`ui/src/components/settings/notification-management.tsx` 的接收人类型下拉加
  「全体用户」；选中它时不显示接收者输入框（改为一句说明），「添加」按钮也不再要求填接收者。
  已配置订阅列表里，`all_users` 显示文案而不是空白的 `receiver`。

**为什么在投递时展开，而不是订阅时把账号列表固定下来**：固定下来等于每来一个新人都要
管理员回来补一条订阅，这正是要解决的问题。代价是每次投递多一次
「查全部已启用账号」的查询 —— 相对 SMTP 发送或写站内信可以忽略。

## 3. 行为边界（需要运维知道）

- 停用账号不在「全体用户」范围内：登不进来的人不必再收站提醒与邮件。
- 邮件渠道下没有配置邮箱的账号会被跳过（其余人照常收到）。
- 「全体用户」是**每个事件 × 每个渠道**一条订阅；想「所有安全事件都通知所有人」，仍然要
  按事件各加一条（目前是这样设计的：事件粒度是订阅的语义，不做批量规则）。

## 4. 测试

- 后端（`pkg/notification/service_test.go`）：
  - 订阅建好之后**新建**的账号也会收到（证明是投递时展开）；
  - 停用账号不在收件人里；同一个人被「全体用户」+ 单独订阅命中时只出现一次；
    邮件渠道只取有邮箱的账号。
- 后端（`pkg/notification/handler_test.go`）：`receiverType=all_users` 的请求体（不含
  `receiver` / `receiverId`）返回 201 且落库的 `receiver_id=0`、`receiver=""`；
  未知的接收者类型仍然 400。
- e2e（`e2e/specs/notification-subscription.spec.ts`，本地集群实跑）：在「设置 → 通知 →
  订阅」里把接收人类型选成「全体用户」，不填接收者也能添加，落库的订阅确实没有具体接收者。
- 反证：去掉 `resolveRecipients` 里的展开分支 → 两条后端用例失败；去掉 handler 的
  `all_users` 分支 → handler 用例失败（都被拒成 400）。
