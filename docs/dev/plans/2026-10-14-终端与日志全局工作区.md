# 终端与日志全局工作区

日期：2026-10-14
状态：**已实施**（后端 WebSocket 契约未变，仅前端改造）

## 1. 背景

终端（Pod / 节点 / kubectl）与日志查看目前都是**详情页签内的组件**：`pod-detail.tsx`、
`deployment-detail.tsx` 等页面把 `<Terminal>` / `<LogViewer>` 直接塞进 Tabs 的 content 里。

由此带来两个问题：

- **切页签即断开会话**：React 卸载组件会 `dispose()` xterm 并关闭 WebSocket，Kubernetes 上的
  `exec`/`attach` 会话随之结束。想看别的页面（或想对照另一个 Pod 的日志），必须先放弃当前会话。
- **一次只能看一个**：没有办法同时开着两个终端、或者一个终端加一路日志。

## 2. 目标

把终端与日志从「页面内的组件」上移为**底部常驻工作区**：

1. 终端与日志都作为**会话**存在，打开后切到任意页面都不中断。
2. 支持**多会话并发**（多个终端、多路日志混排），可切换、可单独关闭。
3. 详情页的「日志」「终端」页签保留，但内容改为**启动器**：选好 Pod/容器后把会话开进工作区，
   而不是在页签里就地渲染。

明确不做：会话的生命周期只在**前端内存**里维持，刷新页面或断开连接仍会终止 shell/日志流
（后端 WebSocket 契约不变，与参考实现口径一致）。

## 3. 设计

### 3.1 会话模型（`ui/src/contexts/terminal-context.tsx`）

由「单个 kubectl 终端」扩展为「多会话工作区」，沿用 `terminal-context.tsx` 文件名与
`TerminalProvider` / `useTerminal` 导出（`App.tsx`、`site-header.tsx` 的引用保持不变）。

```ts
type WorkspaceSessionType = 'node' | 'pod' | 'kubectl' | 'logs'
interface WorkspaceSessionSpec { type; title?; subtitle?; clusterName?; namespace?;
  podName?; nodeName?; containerName?; pods?; containers?; initContainers?;
  ephemeralContainers?; labelSelector?; attachContainerName?; source? }
```

- 会话去重 id：`cluster:type:source:namespace:podName:nodeName:containerName:labelSelector`。
  同一目标重复打开时只激活已有会话，不新建。
- 会话里**冻结**开session时的集群名（`getCurrentCluster()`，不能用 `useCluster()`：`TerminalProvider`
  在 `ClusterProvider` 外层），终端组件的 WebSocket 地址据此拼集群参数，避免切换集群后被带到
  错误的集群上重连。
- `activeSessionId` 由 sessions 推导（关闭当前会话后自动落到最后一个会话），不在 setState 的
  updater 里做嵌套 setState。

导出的动作：`openTerminal()`（开一个 kubectl 会话）、`openSession(spec)`、`activateSession(id)`、
`closeSession(id)`、`closeTerminal()`（全部关闭）、`minimizeTerminal()`、`restoreTerminal()`、
`toggleTerminal()`。

### 3.2 工作区面板（`ui/src/components/floating-terminal.tsx`）

- 由「单个 kubectl 终端」改为**渲染全部会话**：顶部会话页签条（图标按类型区分、可单独关闭），
  非活动会话用 CSS `hidden` 隐藏而**不卸载**，从而保住 xterm 与 WebSocket。
- 日志会话**懒挂载、挂载后保活**：`LogViewer` 会起 Monaco 与日志 WebSocket，若一开面板就
  全量挂载，N 路日志会同时占用 N 个 Monaco；因此首次被激活时才挂载，之后隐藏保活。
- 面板背景回到中性 `bg-background`，由终端/日志各自绘制自己的主题背景（日志主题与终端主题
  互相独立）。
- 保留既有的拖拽改高、全屏、最小化、关闭全部；「关闭全部」仍是显式销毁所有会话。右上角提供
  「新建终端」按钮（kubectl，受 `isAdmin && kubectlEnabled` 约束）。
- 面板不再整体按 `isAdmin && kubectlEnabled` 隐藏：Pod/节点终端与日志各有自己的路由权限门
  （`CanAccess(Pods,"exec")` / `CanAccess(Pods,"log")`），把整块面板绑在 kubectl 开关上会连带
  禁掉它们。kubectl 关闭时只过滤掉 kubectl 会话。
- 原先面板里硬编码的 `Kubectl Terminal` / `Fullscreen` / `Minimize` / `Close (ends session)`
  文案改走 i18n（`terminalWorkspace.*`）。

### 3.3 终端组件（`ui/src/components/terminal-content.tsx`）

补齐内嵌到工作区所需的 props：

- `clusterName?`：覆盖内部 `useCluster().currentCluster`，用于冻结会话集群。
- `embeddedToolbar?` + `toolbarPortalElement?`：内嵌模式下把 Pod/容器选择器、主题、字号、清屏等
  工具栏用 `createPortal` 渲染到工作区面板的表头里，避免内嵌后丢失切换 Pod/容器/主题的能力
  （全屏按钮由工作区统一提供，内嵌工具栏里不再重复）。

### 3.4 启动器（`ui/src/components/terminal-launcher.tsx`）

详情页页签里的空态面板：图标 + 说明 + Pod/容器选择器 + 「打开终端 / 打开日志」按钮。点击后调
`openSession`，会话落到工作区。`mode="logs"` 时开启日志会话，`mode="terminal"` 时开启终端
（`type="pod" | "node"`）；`onOpen` 供承载它的弹窗在会话开出去之后自行关闭。

### 3.5 详情页改造

`pod-detail.tsx`、`node-detail.tsx`、`deployment-detail.tsx`、`statefulset-detail.tsx`、
`daemonset-detail.tsx`、`job-detail.tsx`、`helmrelease-detail.tsx` 的「日志」「终端」页签，内容由
`<LogViewer>` / `<Terminal>` 换成 `<TerminalLauncher>`；`deployment-detail.tsx` 的「终端」弹窗
（更多操作里）同样改为启动器，选中后开进工作区并关闭弹窗。

## 4. 已知取舍

- 日志会话的集群作用域跟随「当前集群」：`useLogsWebSocket` 走 `useCluster()`，本次不给日志链路
  增加集群覆盖参数；切换集群时按现行为重连。终端会话则已冻结开session时的集群。
- 会话仅存活于前端内存：刷新、关闭标签页、断网都会终止 shell 与日志流。
- 内嵌终端的安全提示（`write-confirm`）逻辑不变，仍按当前集群判定。
- 工作区表头里的会话工具栏只在宽屏（`lg` 及以上）显示，窄屏仍可回到详情页启动器换容器后重开。
