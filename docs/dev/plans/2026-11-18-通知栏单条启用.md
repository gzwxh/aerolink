# 通知栏改为「同一时间只展示一条公告」

需求：通知栏的公告**有且只有一条展示**。允许在管理端存多条（备用、排期），但同一时间只能
有一条处于启用状态，顶栏只展示这一条。

## 1. 原口径与问题

旧实现允许多条公告同时启用（上限 20 条），顶栏把所有生效公告串成一条滚动轨道：

- 滚动方式取「最强」（paced > continuous > none），速度取最慢、停留与显示时长取最长；
- 管理页因此要提示「本条设置被别的公告盖过」，编辑弹窗与列表里有一组「实际：…」的说明。

这带来的问题：管理员按条配置的滚动参数经常不生效（被别的公告盖掉），页面只能用提示解释；
而顶栏同时滚动多条内容，长公告很难读完。新口径下这些合并与提示都不再需要。

## 2. 方案

### 2.1 后端（权威约束）

- `model.ListActiveAnnouncements` 加 `LIMIT 1`：按 `priority DESC, id DESC` 只返回一条，
  兜住旧数据里多条同时启用的情况。
- 写入侧强制「只有一条启用」：`POST /admin/announcements`、`PUT /admin/announcements/:id`
  在目标公告为启用时，于同一事务内调用 `model.DisableOtherAnnouncements` 把其余公告改成停用。
  失败整体回滚，不留「两条都启用」的中间态。
- 删除原「生效中上限 20 条」的校验（`AnnouncementMaxActive`、`CountActiveAnnouncements`、
  `withinActiveLimit`）——上限的目的（防止顶栏被撑爆）已由「只能启用一条」覆盖。
- 新增启动归一 `MigrateAnnouncementSingleEnabled`：旧数据若有多条启用，保留顶栏本来就会
  展示的那条（`priority DESC, id DESC`），其余置为停用。只动 `enabled`，不删除任何公告；
  幂等，可在每次启动时执行（受 `DB_MIGRATE=off` 控制，与既有回填一致）。
- 没有库结构变更，不需要额外的升级 SQL。

### 2.2 前端

- 管理页删掉「多条合并成一条轨道」相关的说明与冲突提示（`data-scroll-mode-actual`、
  `data-scroll-params-actual`、编辑弹窗里的两段 warning），单条的配置就是最终效果。
- 页面说明与「启用」提示改为：同一时间只展示启用的那条，启用这条会自动停用其他公告。
- 顶栏组件不需要改动：后端至多返回一条，滚动参数按这一条自己的配置走。

## 3. 验证

- `go test ./pkg/announcement ./pkg/model`：
  - 新建/编辑为启用时，其余公告被停用；
  - 存成停用的公告不影响当前启用的那条；
  - 旧数据多条启用时，生效列表只返回优先级最高的一条；
  - 归一回填只保留一条启用且幂等。
- `pnpm --dir ui exec vitest run src/components/settings/announcement-management.test.tsx
  src/components/announcement-bar.test.tsx src/lib/announcement-scroll.test.ts`
- `pnpm --dir ui exec tsc --noEmit -p tsconfig.app.json`

## 4. 取舍

- 不把公告表改成「单行配置」：多条记录仍有价值（停用备用、按时间手工切换），且避免一次
  破坏性迁移。
- 启动归一不删数据、只改启用标记：升级后顶栏展示的内容与升级前保持一致（旧实现里也只有
  优先级最高的那条最容易读到），管理员可随时重新启用任意一条。
