# 标签页会话闸门（关掉所有页面后再进要重新登录）

## 背景

登录态只存在 HttpOnly Cookie `auth_token` 里，是整个浏览器共享的：关掉某一个标签页
不会让它失效，后端也无法区分「同一次使用的另一个标签页」和「关了页面重新进来」。
安全设置里的「会话在浏览器关闭时过期」（`session_expire_on_browser_close`）把 Cookie
发成会话 Cookie，但 Chrome/Firefox 的「继续浏览上次打开的网页」「恢复关闭的标签页」
会把它一并恢复，因此实测「关掉页面再打开链接仍然免登录」。

目标语义：**同浏览器所有 AeroLink 页面都关掉之后，再进来要重新登录**；在此之前
（刷新、复制标签、从别的标签点链接/复制地址栏开新标签）不打扰用户。

## 方案

纯前端，服务端不参与，鉴权仍只认 Cookie。

1. **票据**：`sessionStorage` 存 `aerolink_tab_session`。它的生命周期正好是标签页——
   刷新、复制标签、同源新标签都带着它，标签页一关就没了。登录成功（密码/LDAP、
   OAuth 往返、MFA 二次验证）与闸门放行时写入；主动退出时清除。
2. **闸门**：`AuthProvider` 在 bootstrap 返回 user 之后判定一次（`tabGate`）。有票据
   直接放行；没有票据时先向同浏览器的其它标签广播 `ping`（`BroadcastChannel`
   `aerolink-tab-session`，250 ms 上限），有标签回 `pong` 就补一张票据放行（复制链接
   到新标签、在别的标签里继续操作都算同一次使用），一个都不回才整页跳到
   `/login?forced=1&reason=session-ended`。
3. **只回 pong 的标签**：仍持有票据且已登录的标签才回应；登录页、已登出的标签保持沉默，
   否则一个已经退出的标签能把别人的新标签「续」上。
4. **登录页提示**：`reason=session-ended` 时在表单上方显示一条 `info` 提示
   （「需要重新登录 / 会话已结束，请重新登录后继续。」），不是弹窗，也不是错误态。
5. 判定期间把 `isLoading` 置真，路由守卫转圈，避免先画出主界面再整页跳走。

## 行为对照

| 打开方式 | 结果 |
| --- | --- |
| 刷新当前页 | 免登录 |
| 复制标签页 / 从已有页面 Ctrl+点击开新标签 | 免登录（sessionStorage 被克隆） |
| 复制地址栏链接，粘到新标签 | 免登录（原标签回 pong） |
| 关掉所有标签后重新打开 | 重新登录 + 登录页提示 |
| 关掉浏览器再启动（未恢复上次会话） | 重新登录（会话 Cookie 已失效） |

## 刻意不做

- **不在 `beforeunload`/`pagehide` 里发登出请求**：刷新、页面内跳转、误关都会触发，
  而且会把同浏览器的其它标签一起踢下线。
- **不在闸门判定失败时删 Cookie**：Cookie 是浏览器共享的，删了会连带登出仍在用的标签；
  跳登录页即可，重新登录会覆盖它。

## 已知边界

- 浏览器「继续浏览上次打开的网页」会把 `sessionStorage` 一起恢复，这种情况下浏览器
  重启后仍然免登录。这一层交给服务端策略（`session_max_hours` 绝对时长）兜底。
- 不在浏览器基线内的浏览器没有 `BroadcastChannel`，探测按「需要重新登录」处理
  （fail-closed），表现为每个新标签都要登录一次。
- 登录页不做闸门判定：否则被闸门赶过去后会在登录页再判一次，整页跳转成环。

## 验证

- `ui/src/lib/tab-session.test.ts`：票据读写、`shouldRequireLogin` 的三种组合、
  探测在无 `BroadcastChannel`/无回应时的结果、持有票据与未持有票据的标签对 ping 的回应
  （用两份模块实例模拟两个标签）。
- `pnpm --dir ui exec tsc --noEmit -p tsconfig.app.json`、`pnpm --dir ui exec vitest run`。
- 手工：两个标签同时开着 → 复制地址栏到新标签免登录；全部关掉后重开 → 落到登录页
  并显示提示。
