# 第 6 步：权限不够怎么办

## 先理解一件事

界面是**按权限渲染**的：没有权限的入口不显示、没有权限的资源不出现在列表里。所以"按钮不见了""点了没反应""列表是空的"大多数是权限问题，不是故障。

| 现象 | 含义 |
| --- | --- |
| 看不到「+ 创建资源」、系统设置、Kubectl 终端 | 当前账号没有对应权限 |
| 页面显示「无权限访问 / 您没有权限查看此页面」 | 该页面需要更高的权限 |
| 提交时报「你没有权限在命名空间 X 中创建 Y」 | 缺命名空间级授权，或动作被限制 |
| 集群处报「你没有权限访问此集群，请联系管理员」 | 这个集群没有授权给你 |
| 列表是空的，但同事能看到 | 大概率没有该命名空间的读权限 |

想确认自己的角色，打开头像菜单，那里显示当前的登录来源与角色名。

## 申请权限怎么说

把 Four 要素一次说清，管理员一次就能配好，不用来回问：

```
集群：prod-cluster
命名空间：payment
资源：pods、deployments
动作：查看、编辑（不含删除）
原因：排查支付服务发版问题
期限：长期 / 到本月末
```

要"能看不能改"就说只读；要发版就说编辑镜像与扩缩容；删除、删除命名空间这类高动作建议单独说明原因。

## 管理员会做什么

管理员在「权限管理」里把角色绑到你的账号（或你所在的用户组）上：

- 角色决定"能做哪些动作、作用于哪些资源类型"；
- 权限绑定决定"这些动作在哪些集群、哪些命名空间生效"。

配法与内置角色（只读管理员、集群只读管理员等）见 [RBAC 配置](../config/rbac-config.md) 和[用户管理](../config/user-management.md)。绑定是管理员侧的活，你只需要把上面的四要素发过去。

::: tip 你有 kubectl 的话可以自查
`kubectl auth can-i get pods -n payment` 这类命令能直接告诉你当前身份有没有某个动作的权限，比反复点界面快。
:::

## 常见误解

| 误解 | 事实 |
| --- | --- |
| "我上次能用，现在不能了" | 角色或绑定被调整了，问管理员要变更记录 |
| "同事能看，我也应该能看" | 权限是绑到账号/用户组上的，不是按部门默认继承 |
| "页面报无权限，是不是系统坏了" | 这是权限判定结果，不是错误 |
| "给我管理员角色最快" | 管理员角色包含删除与密钥读取等高危动作，按需申请更安全 |
