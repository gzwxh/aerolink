# Job：创建与修改

Job 跑一次就结束：它拉起一个或多个 Pod，成功达到「完成数」即置为 Complete，失败按「失败重试次数」重试。数据迁移、批处理、一次性的初始化任务用它。

## 创建入口

左侧「工作负载 → Jobs」→ 右上角「创建」；用例详情页「更多」→「克隆」按现有 Job 复制一份。

Job 是一次性的，所以**没有「副本数量」**——要并行跑几个由「并行度」控制。

![Jobs 列表：① 命名空间筛选 ② 搜索 ③ 创建 ④ 行操作](/images/usage/job-list-guided.png)

列表看「状态 / 完成数」列，`完成 1/1` 表示跑完了；失败的 Job 会保留 Pod 供查日志。

## 顶部身份字段

![Job 创建页：① 命名空间 ② 名称 ③ 描述 ④ 任务参数 ⑤ 创建按钮](/images/usage/create-job-form-guided.png)

图上编号：① 命名空间 ② 名称 ③ 描述 ④ 左侧「任务参数」（失败重试次数、并行度、完成数）⑤ 创建按钮。

| 字段 | 说明 |
| --- | --- |
| 命名空间 | 默认当前命名空间 |
| 名称 | 必填，创建后不可改 |
| 描述 | 写进注解 |

## 页签

页签是 **Job**、**Pod**、`container-1`(+「+ 添加容器」)、**编辑 YAML 并创建**。

### 任务参数

Job 页签里除标签 & 注释外，还有「任务参数」：

| 界面上的字段 | 对应字段 | 说明 |
| --- | --- | --- |
| 失败重试次数 | `backoffLimit` | Pod 失败后最多重试几次，超过就标记失败 |
| 并行度 | `parallelism` | 同时跑几个 Pod |
| 完成数 | `completions` | 需要成功几次才算完成 |

这个页签在 Job 上不提供升级策略，会显示「该资源类型不支持升级策略配置。」。

### 容器的命令要写对

Job 的 Pod 里，容器进程退出码 0 才算成功。用默认镜像（nginx 之类常驻进程）会一直跑不完，所以：

- 在容器页签的**命令与参数**里写清楚要执行什么（如 `sh -c 'echo done'`）。
- 或在「编辑 YAML 并创建」里直接写 `command` / `args`。

### restartPolicy 由表单固定

Job 的 Pod 模板必须声明 `restartPolicy`，表单固定写成 `OnFailure`（不写会被 API 拒绝）。改不了这一项；线上对象如果是 `Never`，编辑保存时表单会沿用线上值，不会误触发模板变更。

## 建完之后

详情页会列出这次 Job 拉起的 Pod，可以看日志、看事件、进容器终端。Job 完成后 Pod 不会自动消失（留着给你看日志），清理靠 `ttlSecondsAfterFinished` 或手工删除。

## 修改

Job 能改的很少，这是 Kubernetes 的限制，不是界面的：

| 改什么 | 怎么改 |
| --- | --- |
| 并行度、失败重试次数这类任务参数 | 行操作「编辑」进表单页 |
| Pod 模板（镜像、命令、环境变量、挂载） | **改不了**，`spec.template` 不可变，API 会返回 `field is immutable` |
| 其他字段 | 详情页「YAML」页签，能不能存下去看 apiserver |

所以 Job 的行操作里**没有「修改镜像版本」**。要换镜像或改命令，只能删掉重建一个 Job（名字要换，除非先删旧的）。

同理，`completions` 也是不可变的。
