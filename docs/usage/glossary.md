# 名词解释：界面上的词都是什么意思

这页给第一次接触 Kubernetes 的人：每个词一句话解释，外加"在界面哪里会见到它"。看文档或截图时遇到不认识的词，回这里查即可。

## 先记住三个

| 名词 | 一句话解释 | 在哪见到 |
| --- | --- | --- |
| 集群（Cluster） | 一整套 Kubernetes 运行环境。公司通常分开发、测试、生产等多套 | 左上角集群切换器 |
| 命名空间（Namespace） | 集群里的"项目文件夹"，资源都归属某个命名空间 | 列表页的命名空间筛选、创建表单的命名空间下拉 |
| 资源（Resource） | Kubernetes 里所有对象的统称，Deployment、Pod、Service 都是资源 | 左侧栏的各个菜单 |

::: tip 看不到东西时先查这两个
**集群选错**和**命名空间选错**是多集群环境里"资源不见了"的头号原因，见[找不到资源](./resources.md#看不到资源)。
:::

## 工作负载：跑程序的东西

| 名词 | 一句话解释 | 在哪见到 |
| --- | --- | --- |
| Pod | 最小的运行单元，可以理解成"一个或几个绑在一起的容器"。Pod 挂掉会被重建，名字也会变 | 左侧栏 → 工作负载 → Pods |
| Deployment | 最常用的应用管理器：保持指定数量的 Pod 在跑，支持滚动更新与回滚。日常发版改的就是它 | 左侧栏 → Deployments |
| StatefulSet | 有状态应用（数据库、中间件）专用：Pod 有固定名字和存储，重启后身份不变 | 左侧栏 → StatefulSets |
| DaemonSet | 保证每个节点都跑一个 Pod，典型用途是日志采集、网络插件 | 左侧栏 → DaemonSets |
| Job | 跑一次就结束的任务，比如数据迁移、批处理 | 左侧栏 → Jobs |
| CronJob | 按时间表（cron 表达式）周期性创建 Job 的任务 | 左侧栏 → CronJobs |
| 副本数（Replicas） | 要同时跑几个相同的 Pod。改这个数字就是"扩缩容" | 列表的「副本」列、扩缩容弹窗 |
| 容器（Container） | 真正跑程序的进程环境；一个 Pod 可以装多个容器 | 详情页的「容器」页签、日志工作区 |
| 镜像（Image） | 容器的"安装包"，写法 `镜像名:版本`，例如 `nginx:1.27` | 创建 / 编辑表单的「容器镜像」 |

## 网络与访问

| 名词 | 一句话解释 | 在哪见到 |
| --- | --- | --- |
| Service | 给一组 Pod 一个固定的访问入口（IP / 域名），Pod 换了也不影响访问 | 左侧栏 → 流量 → Services |
| Ingress | 从集群外访问服务的 HTTP 路由规则（域名、路径转发） | 左侧栏 → 流量 → Ingresses |
| 端口（Port） | 容器里程序监听的端口号，比如 8080 | 创建表单的「端口」、Service 详情 |
| Endpoints | Service 实际转发到的 Pod 地址列表 | 详情页右侧相关资源 |

## 配置与存储

| 名词 | 一句话解释 | 在哪见到 |
| --- | --- | --- |
| ConfigMap | 放非敏感配置：配置文件、环境变量 | 左侧栏 → 配置 → ConfigMaps |
| Secret | 放敏感信息：密码、密钥、证书；界面默认掩码显示 | 左侧栏 → 配置 → Secrets |
| 卷（Volume） | 挂进容器里的目录，可以是临时目录、配置或持久存储 | 创建表单的「存储」 |
| PVC | "申请一块持久存储"的声明；**删除 PVC 数据可能一起没** | 左侧栏 → 存储 → PVCs |
| PV / StorageClass | 集群级的存储资源与存储类型模板，一般由管理员维护 | 左侧栏 → 存储 |

## 状态与排障

| 名词 | 一句话解释 | 在哪见到 |
| --- | --- | --- |
| 事件（Event） | Kubernetes 记录的状态变化。调度失败、拉镜像失败、探针失败都写在这里 | 详情页「事件」页签、右侧栏事件 |
| 探针（Probe） | 定期检查容器"活着吗 / 能接流量吗"的机制，失败会被重启或摘流量 | 编辑表单的「健康检查」 |
| 标签（Label） | 贴在资源上的键值对（如 `app=web`），用来筛选和关联对象 | 列表筛选、详情页「标签」 |
| 选择器（Selector） | 用标签"挑对象"的规则；Service 靠它找到后端 Pod | 详情页的「选择器」 |
| 注解（Annotation） | 贴在资源上的补充说明，不参与筛选 | 行操作「管理注解」 |
| 资源限制（Requests / Limits） | 容器"保底要多少 / 最多能用多少" CPU 与内存 | 创建表单的「资源」、概览的 CPU / 内存卡片 |
| 滚动更新（RollingUpdate） | 逐个替换旧 Pod 的更新方式，过程中服务不中断 | 工作负载详情「策略」 |
| 回滚（Rollback） | 把工作负载退回到历史版本 | 行操作「回滚」、详情页「历史」页签 |
| 节点（Node） | 真正跑 Pod 的机器，可以是物理机或虚拟机 | 左侧栏 → 集群 → Nodes |

## 权限相关

| 名词 | 一句话解释 | 在哪见到 |
| --- | --- | --- |
| 角色（Role） | 一组"能对哪些资源做哪些动作"的定义，如只读、编辑 | 系统设置 → 权限管理 → 角色 |
| 权限绑定（Binding） | 把角色绑到人（或用户组）上，并限定在哪些集群 / 命名空间生效 | 权限管理 → 权限绑定 |
| 命名空间配额（Quota） | 一个命名空间最多能用多少 CPU、内存、存储、Pod 数 | 左侧栏 → 其他 → ResourceQuotas（默认隐藏，可在「自定义侧边栏」打开） |
